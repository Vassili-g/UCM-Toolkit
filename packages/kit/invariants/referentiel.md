# Référentiel

- **Deux formes d'un même mot observées à une place partagée donnent une question quand ni le pluriel ni la terminaison ne les relient.** Indice `synonymes` ; aucune forme seule sans terme UCM unique ; les réponses distinctes, voulues ou reportées écartent la question. Deux termes UCM synonymes dans le fichier (deux membres d'un groupe de `SYNONYMES_COURANTS`, identifiants ou formes tolérées d'un registre : `error` et `danger`, `separator` et `divider`) donnent la question même sans place partagée, rien n'est coché, le terme le plus employé est proposé. Un seul des deux ne donne rien. Autorité : `src/referentiel/questions.ts` `detecterParEtapes`. Tests : `tests/questionsReferentiel.test.ts` (`gray`/`grey`).

- **Une définition UCM (crans, modes, profils, états, collections, rôles du thème, garanties, rôle des produits, tags des règles d'usage, conventions de noms) se modifie dans [`src/referentiel/`](../src/referentiel/), jamais dans un paquet.** Tests : `/tests/referentielUnique.test.ts` refuse la liste qui la recopie.
- **Un tracé non vide appartient à un seul signe de `SIGNES`.** Une autre famille le déclare dans `REPRISES_DE_SIGNES`, avec son libellé. Autorité : `src/referentiel/signes.ts`. Tests : `tests/signes.test.ts`.
- **Les formes d'alerte restent dans le socle.** Les cinq `FORMES` de `packages/plugin-socle/src/ui/Alerte.ts` ne se recopient pas dans `SIGNES`. Un signe se dessine sur une grille de 16, sauf s'il déclare `grille`, et `hauteur` quand elle n'est pas carrée. Autorité : `src/referentiel/signes.ts`. Tests : `tests/signes.test.ts`.
- **Chaque signe dit son emploi, chaque famille sa pose.** `emploi` dit quand prendre le signe et lequel prendre à sa place, `pose` la fonction du socle, les tailles, la teinte et le nom accessible. Ce sont des phrases pour un lecteur : le socle n'en dérive rien par code. `POSE_DES_ALERTES` décrit la pose des alertes, dont les formes restent au socle. Autorité : `src/referentiel/signes.ts`. Tests : `tests/signes.test.ts`.
- **`SIZE_VALUES` est la projection de `REGISTRE_TAILLES` (identifiants et formes tolérées), et `estUneValeurDesactivee` lit `REGISTRE_ETATS` par `termeReconnu`.** `tiny` est toléré de `xs`, `huge` de `xl`. Un axe dont toutes les valeurs sont dans `SIZE_VALUES` se publie `size` : un axe `Size=Tiny|Huge` reste `size`. Autorité : `src/referentiel/vocabulaire.ts`, `src/format/names.ts` `estUneValeurDesactivee`. Tests : `/tests/referentielUnique.test.ts`, `tests/valeurDesactivee.test.ts`, `tests/referentiel.test.ts`.
- **Après une modification du référentiel, relancer les tests, régénérer la vue illustrée (`generer-donnees-referentiel.ts`), régénérer la planche du moteur (`npm run planche --workspace ucm-couleur`) si le moteur ou ses crans changent, et changer la version de `@ucm-kit/core`.**
- **Un composant imbriqué se classe par `sorteDeLImbrique`, dans cet ordre : dépendance (`.componentRules` le nomme), wrapper de dimensions (dimensions de layout liées), pièce interne (préfixe `.` ou `_`), détail.** Le socle et le relevé d'Architect relèvent les faits, puis appellent la fonction ; aucun ne teste le préfixe ni les dimensions pour classer. Une liaison que l'instance tient sans changement de son composant principal n'est jamais jugée (C80, C20, C19), quelle que soit la sorte ; une surcharge de l'hôte l'est et vise un token de l'hôte. Autorité : `src/referentiel/composition.ts` `sorteDeLImbrique`, `src/controles/couche.ts` `controlerCouchesParEtapes`, `src/controles/mapping.ts` `controlerMappingParEtapes`. Tests : `tests/composition.test.ts`, `tests/controles-composant.test.ts`, `packages/plugin-socle/tests/imbriquesParLeKit.test.ts`, `packages/plugin-architect/tests/imbriquesParLeKit.test.ts`.
- **Une valeur de variant s'écrit en toutes lettres, son token en abréviation.** Le variant prend une majuscule à chaque mot (`Small`, `Extra Large`, `Danger`), le token des minuscules (`sm`, `xl`, `danger`). `ecritureDuVariant` passe de l'un à l'autre, et `S`, `M`, `L`, `sm`, `Middle` et `Error` reçoivent une correction vers le mot entier. `segmentDeToken` change le point et la barre en tiret. C10 (taille) et C8 (palette) lisent ces deux écritures : un token qui n'est pas l'identifiant (`small` pour `sm`, `error` pour `danger`) reçoit C8 ou C10 vers l'identifiant, un variant qui n'est pas le mot entier reçoit le même code avec une correction `nom-de-valeur` (absente quand le mot entier est déjà une valeur de l'axe), et la casse seule d'un terme connu ne donne rien. Autorité : `src/referentiel/ecriture-des-mots.ts`, `TAILLES_DE_VARIANT` de `src/referentiel/vocabulaire.ts`, `controlerNommage` de `src/controles/nommage.ts`. Tests : `tests/valeursDeVariant.test.ts`, `tests/axes-et-valeurs-de-variant.test.ts`.
- **Le rôle d'un nom d'axe vient du référentiel.** `NOMS_D_AXES` et `NOMS_D_AXES_FRANCAIS` le donnent, et un interrupteur de `INTERRUPTEURS` ne pilote aucun segment. Le nom décide : un segment qui vaut une valeur de l'axe se lit à la position de cet axe avant tout terme d'un autre registre (un axe `Variant` à valeurs `primary` et `danger` reste un style). Deux axes de style donnent un constat à faire C63 `deux-axes-de-style`, sans fusion ; un token du style `subtle` qui vise `solid`, ou du style `solid` qui vise `surface`, donne C63 `style-et-dossier`. Autorité : `src/referentiel/architecture.ts`, `axeDePropriete` et `controlerNommage` de `src/controles/nommage.ts`. Tests : `tests/rolesDesNomsDAxe.test.ts`, `tests/axes-et-valeurs-de-variant.test.ts`.
- **Un layer est une icône, un anneau ou un séparateur selon `src/referentiel/layers.ts`, jamais selon une expression propre à un contrôle.** Une icône est l'instance d'un composant dont le nom dit icône, l'instance qu'une propriété d'échange d'instance pilote sous un nom d'icône, ou un VECTOR ou BOOLEAN_OPERATION dont le nom contient un mot entier de `MOTS_D_ICONE`. Un FRAME ou un TEXT n'en est jamais une. Le tracé que la surcharge d'une instance d'icône peint, posée comme composant d'icône ou pilotée par un échange d'instance, est une icône sous n'importe quel nom (`mapping.ts` `rolesAdmisDuLayer`). Un anneau est nommé `Ring` ou `Focus ring`, ou lié à un token de rôle `ring`. Seuls `divider`, `ring` et `icon` désignent un layer par son nom. Un anneau rempli sans contour se mesure sur son remplissage ; une instance d'anneau sans peinture propre compte quand un descendant visible se peint. Autorité : `src/referentiel/layers.ts`, `src/controles/accessibilite.ts` `anneauxDuVariant`. Tests : `tests/definitionsDeLayer.test.ts`, `tests/iconeDansLesControles.test.ts`, `tests/accessibilite.test.ts` (E9.9).
- **Une faute se juge sur la longueur du mot, jamais sur le nombre d'emplois ni sur la place.** Un mot de 7 lettres au moins à une lettre d'un terme connu (échange compris), ou de 8 lettres à deux lettres, donne une question de faute vers le terme UCM, même si le terme manque au fichier. De 3 à 6 lettres, un mot à une lettre d'un terme connu est une faute s'il n'est pas dans `motConnu` (mots anglais courants et segments des design systems) ; à 3 lettres, un seul terme du kit doit être à une lettre du mot (`tex` près de `text`) ; un mot de moins de 3 lettres n'en est jamais une, et le dictionnaire n'est lu que pour un mot qui a déjà un terme proche. Le dictionnaire se régénère par `scripts/generer-mots-connus.ts`, et la mesure des faux positifs en retire le système mesuré. La référence tolérée vaut son terme UCM, et une négation n'est jamais une faute. Le dictionnaire (`FORMES_D_UN_MEME_MOT`, `MOTS_DISTINCTS`) classe les couples : un couple absent des deux, de deux mots hors vocabulaire à une lettre près et au seuil de 7 lettres, devient une question `ecriture-proche`. Les mots d'un nom de composant que le kit connaît (`btton` près de `button`) se lisent de même pour la faute seulement. Le morceau de 3 lettres au moins d'un mot de casse mixte (`controlItemBgAmctive`, `colorwWhite`) se lit pour la faute seulement, avec les mêmes seuils et le même dictionnaire, jamais pour les paires ni les mots collés. La forme soudée d'un terme de plusieurs mots (`paddingx`) est une écriture du terme, et sa faute (`fontsttyle`) propose le terme à tirets. Un renommage de forme tolérée bloqué par collision, un synonyme seul au terme UCM unique et un pluriel de terme sans singulier donnent une question de paire, y compris pour une abréviation (`bgs`) et un terme composé (`focus-rings`). Un mot collé qui se coupe en termes exacts dont un terme de `REGISTRES_COMPOSANTS` (`paddingwidth`) donne une question `mots-colles` ; ces termes restent hors de `decouperPourQuestions`. `npm run stress:f1 -- --faux-positifs` fixe les seuils. Autorité : `src/referentiel/questions.ts`, `src/referentiel/termes-connus.ts`, `src/referentiel/mots-connus.ts`, `src/referentiel/vocabulaire.ts`. Tests : `tests/questionsReferentiel.test.ts`, `tests/dictionnaireDuVocabulaire.test.ts`.
- **`states`, `etat` et `état` se renomment en `state` dans toute catégorie ; `status` est un mot à part.** `REGISTRE_AXES_ETAT` ne tolère pas `status`, donc `estLAxeDEtats('Status')` et `STATE_AXIS_NAMES` l'écartent et `status/success` ne change pas. Autorité : `src/referentiel/vocabulaire.ts` `REGISTRE_AXES_ETAT`. Tests : `tests/axeDEtatsUnique.test.ts`, `tests/vocabulaireDuFichier.test.ts`, `tests/normalisationReferentiel.test.ts`.
- **Une forme soudée du registre se coupe où qu'elle soit dans le segment.** `fontfamily-thin` donne `font`, `family`, `thin` comme `fontfamily` seul, donc le renommage remplace la forme tolérée dans un nom composé. Autorité : `src/referentiel/ecriture-des-mots.ts` `decouperSegment`. Tests : `tests/lexiqueReferentiel.test.ts`.
- **Le renommage est idempotent.** Appliqué à ses propres sorties, il ne renomme rien : `ecritureStable` (`src/referentiel/lexique.ts`) reprend l'écriture d'un segment jusqu'à ce que sa relecture ne la change plus. Borne : `BRANCHES_MAXIMALES_PAR_CLE` (50) limite les branches parallèles comparées par clé, pour le coût en paires. Tests : `tests/lexiqueReferentiel.test.ts`, `tests/stressF1Harnais.test.ts`.
- **L'icône d'un composant est une instance d'`Icon`, son fill suit un token `icon` ou `foreground` du composant, sa propriété `Size` suit la taille du variant (C66).** Sans fill visible, le trait tient lieu de couleur et C17 y admet `icon` ou `foreground`. Largeur et hauteur ne se jugent plus. Le token attendu est celui dont chaque segment d'axe vaut celui du variant et dont l'élément nomme le layer ; un constat regroupe les variants et ne nomme `attendu` que si tous attendent les mêmes tokens. Borne : `Size` ne se juge que si le relevé la porte (`instanceDe.valeurs`) et qu'elle dit une taille. Autorité : `controlerLaTypographie` de `src/controles/typographie.ts`, `rolesAdmisDuLayer` de `src/controles/mapping.ts`, `tokenVautPourLeLayer` de `src/controles/nommage.ts`. Tests : `tests/icones-du-composant.test.ts`, `tests/typographie.test.ts`.
- **C31 ne liste que 200 variants absents et ne cherche rien au-delà de 4 096 combinaisons ; il le dit par une information.** Une valeur répétée dans un axe compte une fois. Les informations `et-autres` et `au-dela-de-la-borne` sont de type `info` et portent `faits.genre`. Autorité : `controlerOublisParEtapes` de `src/controles/oublis.ts`. Tests : `tests/matrice-et-tokens-sans-emploi.test.ts`.
- **C32 dit `nom-illisible` d'un token du composant que la grammaire ne lit pas, et ne dit `inutilise` ni d'un token qu'une liaison illisible de sa nature peut lier, ni d'une palette hors registre.** Un segment d'élément qui ne nomme aucun layer du composant, dans un jeu qui a un axe de palette, est une palette hors registre : le token est `sans-variant`. Autorité : `controlerOublisParEtapes` de `src/controles/oublis.ts`. Tests : `tests/matrice-et-tokens-sans-emploi.test.ts`.
