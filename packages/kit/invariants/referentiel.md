# Référentiel

- **Une définition UCM (crans, modes, profils, états, collections, rôles du thème, garanties, rôle des produits, tags des règles d'usage, conventions de noms) se modifie dans [`src/referentiel/`](../src/referentiel/), jamais dans un paquet.** Tests : `/tests/referentielUnique.test.ts` refuse la liste qui la recopie.
- **Après une modification du référentiel, relancer les tests, régénérer la vue illustrée (`generer-donnees-referentiel.ts`), régénérer la planche du moteur (`npm run planche --workspace ucm-couleur`) si le moteur ou ses crans changent, et changer la version de `@ucm-kit/core`.**
- **Un composant imbriqué se classe par `sorteDeLImbrique`, dans cet ordre : dépendance (`.componentRules` le nomme), wrapper de dimensions (dimensions de layout liées), pièce interne (préfixe `.` ou `_`), détail.** Le socle et le relevé d'Architect relèvent les faits, puis appellent la fonction ; aucun ne teste le préfixe ni les dimensions pour classer. Pièce interne ou wrapper : une liaison tenue du composant principal peut viser `theme` ou `layout` sans C80 ; une surcharge de l'hôte vise un token de l'hôte. Autorité : `src/referentiel/composition.ts` `sorteDeLImbrique`, `src/controles/couche.ts` `controlerCouchesParEtapes`. Tests : `tests/composition.test.ts`, `tests/controles-composant.test.ts`, `packages/plugin-socle/tests/imbriquesParLeKit.test.ts`, `packages/plugin-architect/tests/imbriquesParLeKit.test.ts`.
