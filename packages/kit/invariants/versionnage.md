# Versionnage

- **Une propagation entre layers homonymes nomme leur parent lu sans proposer de liaison.** `faits.parent` porte le nom du parent du variant visé, seulement s'il figure dans le relevé. Autorité : `src/controles/propagation.ts` `constatDeLaPropagation`. Tests : `tests/propagation.test.ts`.
- **Un champ dont la lecture a échoué ne reçoit aucune proposition de propagation et ne compte pas dans C81.** Le relevé ne dit pas qu'il est en dur. Autorité : `src/controles/propagation.ts` `constatDeLaPropagation` (`lectureManquee`). Tests : `tests/propagation.test.ts`.
- **L'écriture de la désactivation que C53 porte dans `faits.ecriture` est la plus répandue parmi les variants désactivés, à égalité la première par ordre alphabétique.** L'ordre des variants ne change aucun fait. Autorité : `src/controles/accessibilite.ts` `controlerLAccessibiliteParEtapes`. Tests : `tests/accessibilite.test.ts` (E9.10).

- **Un changement de forme du JSON incrémente `contractVersion` et met à jour la spec et les consommateurs.**
- **Le kit qui connaît une nouvelle version du format de tokens sort avec la CLI et l'adaptateur, le kit en premier, avant le plugin qui la produit.** Spec : [compatibilité](../../../docs/format/COMPATIBILITE.md#lordre-dune-nouvelle-version-du-format-de-tokens)
- **`schema/ucm-contract.schema.json` est dérivé de `src/format/types.ts` par `npm run schema`, jamais rédigé.** Il décrit la forme et ignore la cohérence : renvois internes, format des valeurs tokenisées. Il ne remplace aucun contrôle du consommateur. Sa propre `description` énonce ses limites.
- **`src/controles/integrite.ts` `controlerLIntegriteUcm` (C82) juge le catalogue contre la structure UCM ; `src/controles/structure.ts` `controlerLeCatalogue` juge scopes, échelles et alias de mode sans elle.** Les deux lisent le seul catalogue, sans composant, et aucun n'appelle l'autre. C82 rend [] sans collection `theme` lue, sauf l'information `theme-non-reconnu` quand le fichier reconnaît une collection UCM et aucune `theme` ; un fichier sans aucun rôle reconnu reste muet. Une création ou un cran n'est corrigé que si la règle et le fichier donnent un seul résultat ; sinon le constat reste sans correction, avec sa `raison`, ou devient une question à deux candidats. Tests : `tests/integrite.absentes.test.ts`, `tests/integrite.crans.test.ts`, `tests/integrite.structure.test.ts`.
- **Un doublon d'échelle compare les valeurs résolues, alias suivis, à 1e-6 près, pour toute échelle de `layout` ; une cible inaccessible sans library choisie donne l'information `cible-inaccessible`, une par collection.** Un cran est un nombre ou une taille du registre ; une propriété (`padding/x`) n'en est pas un. Borne : alias en boucle, absent ou non numérique : le cran ne joue pas. Autorité : `src/controles/structure.ts` `controlerLesEchelles`, `controlerLesLibrariesInactives`. Tests : `tests/structure.test.ts`.
- **C63 `theme` vise la variable de la palette dont le rôle a, dans la table du kit et le sens lu, le cran du token dans le mode.** Correction si une seule variable correspond et si le sens n'est pas `partage` ; sinon une question sans présélection. Un rôle écrit deux fois au cran compte pour deux candidates (`doublons` de `lesPrefixes`). Les sœurs ne choisissent pas la cible. C20 se tait sur la liaison d'un token que C63 `theme` accuse déjà : C63 garde sa correction. Autorité : `src/controles/structure.ts` `contournementsDuTheme`, `controlerLesContournements` ; `src/controles/couche.ts` `controlerCouchesParEtapes`. Tests : `tests/structure.test.ts`.
- **C82 juge chaque variable d'un rôle écrit deux fois dans un groupe, puis pose une seule question `role-en-double` sans case cochée ; une seconde collection `theme` donne `theme-en-double`, sans correction ; l'identifiant de `cran-absent` porte la clé du thème ; une variable `theme` non chargée protège son rôle contre la création ; les scopes d'une couche sans portée sont jugés pour tout type de variable.** Autorité : `src/controles/integrite.ts` `controlerLIntegriteUcm`. Tests : `tests/integrite.structure.test.ts`.
