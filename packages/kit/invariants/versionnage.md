# Versionnage

- **Une propagation entre layers homonymes nomme leur parent lu sans proposer de liaison.** `faits.parent` porte le nom du parent du variant visé, seulement s'il figure dans le relevé. Autorité : `src/controles/propagation.ts` `constatDeLaPropagation`. Tests : `tests/propagation.test.ts`.
- **Un champ dont la lecture a échoué ne reçoit aucune proposition de propagation et ne compte pas dans C81.** Le relevé ne dit pas qu'il est en dur. Autorité : `src/controles/propagation.ts` `constatDeLaPropagation` (`lectureManquee`). Tests : `tests/propagation.test.ts`.
- **L'écriture de la désactivation que C53 porte dans `faits.ecriture` est la plus répandue parmi les variants désactivés, à égalité la première par ordre alphabétique.** L'ordre des variants ne change aucun fait. Autorité : `src/controles/accessibilite.ts` `controlerLAccessibiliteParEtapes`. Tests : `tests/accessibilite.test.ts` (E9.10).

- **Un changement de forme du JSON incrémente `contractVersion` et met à jour la spec et les consommateurs.**
- **Le kit qui connaît une nouvelle version du format de tokens sort avec la CLI et l'adaptateur, le kit en premier, avant le plugin qui la produit.** Spec : [compatibilité](../../../docs/format/COMPATIBILITE.md#lordre-dune-nouvelle-version-du-format-de-tokens)
- **`schema/ucm-contract.schema.json` est dérivé de `src/format/types.ts` par `npm run schema`, jamais rédigé.** Il décrit la forme et ignore la cohérence : renvois internes, format des valeurs tokenisées. Il ne remplace aucun contrôle du consommateur. Sa propre `description` énonce ses limites.
- **`src/controles/integrite.ts` `controlerLIntegriteUcm` (C82) juge le catalogue contre la structure UCM ; `src/controles/structure.ts` `controlerLeCatalogue` juge scopes, échelles et alias de mode sans elle.** Les deux lisent le seul catalogue, sans composant, et aucun n'appelle l'autre. C82 rend [] sans collection `theme` lue, sauf l'information `theme-non-reconnu` quand le fichier reconnaît une collection UCM et aucune `theme` ; un fichier sans aucun rôle reconnu reste muet. Une création ou un cran n'est corrigé que si la règle et le fichier donnent un seul résultat ; sinon le constat reste sans correction, avec sa `raison`, ou devient une question à deux candidats. Tests : `tests/integrite.absentes.test.ts`, `tests/integrite.crans.test.ts`, `tests/integrite.structure.test.ts`.
- **`src/controles/projection-dtcg.ts` `catalogueDepuisTokens` est l'unique conversion d'un `tokens.json` en catalogue.** `ucm check` et le rejeu des fichiers réels (`tests/stress/rejeu-fichiers/dtcg.ts`, qui la réexporte) la lisent. Une collection est une racine sans `$`, ses modes viennent de `com.ucm.axes`, un jeton de type composé est sauté et compté, une cible d'alias absente garde la clé que son chemin donnerait. Le bilan ne porte que des nombres. Tests : `tests/projectionDtcg.test.ts`, `tests/stressRejeuFichiers.test.ts`.
- **Un doublon d'échelle compare les valeurs résolues, alias suivis, à 1e-6 près, pour toute échelle de `layout` ; une cible inaccessible sans library choisie donne l'information `cible-inaccessible`, une par collection.** Un cran est un nombre ou une taille du registre ; une propriété (`padding/x`) n'en est pas un. Borne : alias en boucle, absent ou non numérique : le cran ne joue pas. Autorité : `src/controles/structure.ts` `controlerLesEchelles`, `controlerLesLibrariesInactives`. Tests : `tests/structure.test.ts`.
- **C63 `theme` vise la variable de la palette dont le rôle a, dans la table du kit et le sens lu, le cran du token dans le mode.** Correction si une seule variable correspond et si le sens n'est pas `partage` ; sinon une question sans présélection. Un rôle écrit deux fois au cran compte pour deux candidates (`doublons` de `lesPrefixes`). Les sœurs ne choisissent pas la cible. C20 se tait sur la liaison d'un token que C63 `theme` accuse déjà : C63 garde sa correction. Autorité : `src/controles/structure.ts` `contournementsDuTheme`, `controlerLesContournements` ; `src/controles/couche.ts` `controlerCouchesParEtapes`. Tests : `tests/structure.test.ts`.
- **C82 juge chaque variable d'un rôle écrit deux fois dans un groupe, puis pose une seule question `role-en-double` sans case cochée ; une seconde collection `theme` donne `theme-en-double`, sans correction ; l'identifiant de `cran-absent` porte la clé du thème ; une variable `theme` non chargée protège son rôle contre la création ; les scopes d'une couche sans portée sont jugés pour tout type de variable.** Autorité : `src/controles/integrite.ts` `controlerLIntegriteUcm`. Tests : `tests/integrite.structure.test.ts`.

- **Un module importe le kit par `@ucm-kit/core/modules` seulement.** Les autres portes (`format`, `emplois`, `referentiel`, `controles`, `protocoles`, `nommage`, `lecteurs`, `lecteurs/navigateur`) servent le toolkit (CLI, adaptateur, plugins) et changent sans préavis. Un paquet de `packages/` se déclare module par `"ucmModule": true` dans son `package.json`. Borne : hors du dépôt, une règle ESLint `no-restricted-imports` porte la même règle, sans test ici. Autorité : `/tests/modulesParLaPrise.test.mjs`. Tests : le même fichier, dont des cas fautifs fabriqués (autre porte, chemin relatif vers `packages/kit`, version non exacte).
- **La prise ouvre avec 7 fonctions et le type `Contract`, republiés sous leur nom d'origine.** `lireConfiguration`, `trouverContrats`, `verdictDeVersion`, `vueExacteDuVariant`, `indexerTokensDtcg` viennent de `lecteurs` ; `isTokenReference`, `tokenCssVariable` et `Contract` de `format`. `src/modules/index.d.mts` copie les signatures, `vueExacteDuVariant` avec un retour précis ; la compilation les juge assignables à celles des portes d'origine. Autorité : `src/modules/index.mjs`, `src/modules/index.d.mts`. Tests : `tests/apiPublique.test.mjs`.
- **Un nom entre dans la prise quand le code d'un module l'importe, jamais par anticipation.** Elle promet une question (un verdict, une vue), pas les pièces qu'elle assemble. Un nom qu'aucun module n'importe plus est déprécié. Borne : un module qui réclame plus de trois noms hors de la prise pendant sa conception montre une lecture commune mal découpée ; la prise se redessine avec lui.
- **Aucun nom de `src/referentiel/` n'entre dans la prise.** Un module qui en réclame un révèle un trou du contrat : le corriger dans le format. Tests : `tests/apiPublique.test.mjs`.
- **Chaque nom de la prise a un exemple d'appel sur `fixtures/`, dont le résultat attendu est écrit.** Un type a un extrait TypeScript compilé. Borne : un changement de comportement qu'aucun exemple ne couvre passe ; ajouter un exemple à chaque écart trouvé. Autorité : `tests/prise-exemples.mjs`, `tests/prise-attendus.json`. Tests : `tests/apiPublique.test.mjs`.
- **Toute modification de la prise a une entrée du journal `packages/kit/CHANGELOG.md`, dans une version postérieure à la précédente.** Titre `## <version>`, puis `### ajout`, `### déprécié` ou `### rupture`, les noms entre accents graves, le geste à faire dans un module, une ligne « Décidé par ... », le tout en mots simples. Nom nouveau : `ajout`. `@deprecated` posé : `déprécié`. Nom retiré, signature changée ou résultat attendu changé ou retiré : `rupture`. Une version qui change la prise a une entrée à son numéro. Borne : la version précédente se lit dans Git, au parent du commit qui a posé le numéro, ou à `HEAD` si le numéro ou la prise change dans la copie de travail ; sans historique (clone superficiel), le test échoue en disant de le récupérer. Tests : `tests/apiPublique.test.mjs`.
- **Le chiffre du milieu monte quand la prise ou le format casse, le dernier chiffre pour tout le reste.** Milieu : nom retiré ou renommé, signature changée, résultat différent pour la même entrée, nouvelle majeure de `CONTRACT_VERSION`, nouvelle `TOKENS_FORMAT_VERSION`. Dernier chiffre : changement interne (référentiel, contrôles, plugins, CLI), ajout d'un nom ou d'un champ de résultat, dépréciation. Un changement interne n'a pas d'entrée ; une majeure de contrat ou une version de tokens a une entrée qui renvoie à [CHANGELOG-FORMAT.md](../../../docs/format/CHANGELOG-FORMAT.md). Borne : l'ajout d'un champ de résultat ne se détecte pas, seul l'exemple le voit. Tests : `tests/apiPublique.test.mjs`.
- **Un nom retiré de la prise est d'abord annoncé.** `@deprecated` dans `src/modules/index.d.mts`, avec le nom qui le remplace ; il reste servi au moins une version publiée, puis disparaît à la rupture suivante. Tests : `tests/apiPublique.test.mjs`.
- **Le kit reste en 0.x jusqu'à la 1.0, qui attend deux modules en service qui importent la prise et trois mois sans rupture.** En 1.0 la table se décale d'un cran : l'ajout monte le chiffre du milieu, la rupture le premier, l'interne le dernier. Tests : `tests/apiPublique.test.mjs` refuse un kit en 1.x tant que la règle n'est pas décalée.
- **Un repository n'a qu'un kit : un module épingle la version exacte du kit que la CLI du repository épingle.** Sans `^` ni lien. `ucm guide` nomme un `@ucm-kit/core` installé à une autre version que celui de la CLI. Autorité : `cli/src/guide.mjs` `noyauEnDesaccord`. Tests : `cli/tests/guide.test.mjs`, `/tests/modulesParLaPrise.test.mjs` (module du dépôt).
- **Le chemin `schema/ucm-contract.schema.json` est promis avec la prise.** `ucm init` l'écrit dans les réglages d'éditeur du consommateur. Autorité : `package.json` (`exports["./schema"]`, `files`). Tests : `tests/apiPublique.test.mjs`.
- **Changer la prise se décide avec le mainteneur, jamais par un agent seul.** Un ajout se décide avec le développeur du module, une dépréciation ou une rupture avec le mainteneur et les développeurs. L'agent qui touche à `src/modules/**` rend la question et ne décide pas. Le mainteneur lit l'entrée du journal, pas le code.
