# Corpus de test

- **Le lecteur de contrats se teste sur un corpus figé, `fixtures/contrats/`, de la version précédente : quatre contrats 13.0, et deux contrats 14.0 figés d'avance pour la fenêtre 14.0 et 15.0.** Ce corpus est nécessaire : la fenêtre de lecture à deux versions n'est observable qu'à partir de contrats que le moteur ne produit plus. L'immobilité, défaut de l'instantané côté moteur, est ici la propriété recherchée.
- **Le corpus n'est jamais comparé à une sortie du moteur.** Un tel test serait ce que la règle « le moteur ne se teste sur aucun contrat commité » interdit (`tests-du-moteur.md`).
- **Le corpus n'est jamais rafraîchi.** Un réexport le rendrait inutile, puisqu'il cesserait d'être N-1. Ses empreintes SHA-256, dans le README voisin, empêchent de le croire frais.
- **Le corpus disparaît quand la fenêtre de lecture se referme au-dessus de sa version, en même temps que le code de compatibilité qu'il couvre, jamais avant.**
- **Les jeux 12.0 et 11.0, sortis de la fenêtre, restent en place.** `validation-contrat.mjs` garde le code qui lit la 12.0, la 11.0 et les versions antérieures ; `refus-enregistres.test.mjs` mesure ce code sur eux. Chaque jeu disparaît avec le code qui le lit.
- **Le corpus n'est pas publié.** `files` du kit ne l'inclut pas.
- **`fixtures/tokens/origine/` pose à `tokens.json` la même question que `fixtures/contrats/` : le lecteur se teste sur un instantané figé.** Il porte un fichier de la forme d'origine, antérieure à la version `1` du format de tokens, produit par le moteur d'avant cette version depuis le mock du producteur. Les tests du kit le lisent pour l'état `origine`.
- **Les trois bornes du corpus de contrats valent pour `fixtures/tokens/origine/`.** Aucun test permanent ne le compare à une sortie du moteur. Il n'est jamais rafraîchi, et son empreinte SHA-256 est dans le README voisin. Il disparaît avec le code qui lit la forme d'origine, jamais avant. Il n'est pas publié non plus.
- **`fixtures/dialectes/dialectes.json` relève les noms et valeurs de propriétés que publient 15 design systems, pour le générateur d'Architect.** Aucun texte recopié ; chaque entrée garde son URL et sa date de lecture, chaque système sa licence et l'empreinte de ses sources. Une entrée `verifie: false` ne fournit aucune valeur. Le fichier n'est jamais comparé à une sortie du moteur, se rafraîchit seulement par une nouvelle lecture datée, et n'est pas publié. Autorité : `packages/plugin-socle/tests/generateur/dialectes.ts`. Tests : `packages/plugin-architect/tests/generateur.test.ts`.
