# Nomenclature d'UCM Architect

- **Le kit définit seul les clés, les textes et la lecture des entrées `ecriture`, `terme:`, `ecart:`, `ordinaire:` et `exclues` rangées dans `ESPACE_ARCHITECT`.** Architect y délègue aussi le rangement ordonné et le retour aux textes d'avant si une écriture échoue ; Palettes lit ces mêmes entrées. Autorité : `kit/src/protocoles/nommage.ts` `entreeDeNommage`, `lireLesEntreesDeNommage`, `rangerLesEcritures`. Tests : `kit/tests/protocolesNommage.test.ts`, `tests/nomenclatureRegles.test.ts`, `plugin-palettes/tests/nommageDesPalettes.test.ts`.
- **L'interrupteur « Ce fichier suit l’architecture UCM » de la Configuration range la déclaration `architecture` dans `ESPACE_ARCHITECT`.** Le kit en déclare la clé (`CLE_ARCHITECTURE_DU_FICHIER`), le lecteur et la forme versionnée. Le bilan porte son état lu. L'export et l'import des règles portent ce choix ; un import sans déclaration conserve celle du fichier. Une bascule ne change pas l'Historique.
- **Nomenclature ne change dans le document que le `name` d'une variable ou d'une collection locale, ses données partagées dans `ESPACE_ARCHITECT` et le point d'annulation.** Seul `src/ecriture/noms.ts` le fait. Nomenclature ne lit ni page ni composant. Tests : `tests/loiDEcritureDesNoms.test.ts` refuse ailleurs toute création, suppression, setter de valeur, import, chargement de page et `.remove(`, interface comprise.
- **Une variable que Palettes a écrite ou reprise n'est renommée que si le fichier porte la marque `nommage` de Palettes (JSON `version: 1` à la racine de `ESPACE_PARTAGE`) et que l'écriture est rangée en v2, relue au moment d'écrire.** Sinon elle n'est jamais renommée, même cochée, et son dossier garde son nom. Une collection exclue n'est pas touchée, annulation comprise : l'annulation relit les exclusions au moment d'écrire, saute les lignes de cette collection en `exclue` et les garde au journal, pour une annulation suivante une fois la collection réincluse. La collection qui porte la variable peut être renommée ; Palettes la suit par son identifiant. Avant d'écrire, chaque nom est relu : un objet changé, disparu ou dont le nouveau nom est occupé est sauté, et un lot s'annule en un seul pas. Une annulation saute aussi en `collision` la restitution qui créerait un conflit de chemin de `tokens.json` absent avant le lot ; le journal range les paires déjà en conflit (`dejaEnConflit`), qu'elle peut rétablir. Tests : `tests/nomenclatureEcriture.test.ts` (dont `N01` et `N09`), `tests/nomenclatureProtocole.test.ts` (`N09`), `tests/nomenclatureNomsDePalettes.test.ts`, `/tests/nomsDePalettes.test.ts` (l'aller-retour avec Palettes).
- **Un renommage de collection n'est ni proposé ni écrit quand il ferait écarter des axes de modes de l'export de tokens.** Cas : deux collections à plusieurs modes, ou étendues par une extension locale, dont les noms donnent le même préfixe (`meme-axe`) ; un nom que l'export réserve aux extensions d'un axe (`axe-et-extensions`). Un nom sans préfixe n'est pas contrôlé. `cheminsEnConflit` le juge sur tout le document, collections exclues comprises, d'après les modes que l'inventaire porte ; sans eux, aucun contrôle d'axe. Une collision déjà présente ne bloque rien. Tests : `/tests/axesDeModes.test.ts` compare cette règle à `axesDesCollections` ; `tests/nomenclatureCheminsPublies.test.ts`, `tests/nomenclatureEcriture.test.ts` (`AUD-E2`), `tests/nomenclatureProtocole.test.ts` (`AUD-E2b`).
- **Le moteur (vocabulaire, lexique, normalisation, questions) et les données UCM viennent de `@ucm-kit/core/referentiel`.** Le plugin n'en recopie aucune. Tests : `/tests/referentielUnique.test.ts`.
- **Le calcul des noms est une fonction pure d'une entrée sérialisable, hors du sandbox.** `EntreeDuCalcul` = génération, inventaire (protections, refus de lecture et marque de Palettes compris) et règles du fichier ; `structuredClone` la copie sans perte. Le `Bilan` qu'elle rend est celui que la session envoie, dans son ordre complet. La session mène `calculerTout` par tranches et ne change ni résultat ni cessions. Borne : le module n'importe ni `figma`, ni le journal `src/lecture.ts`, ni `ucm-plugin-socle/src/ui/` ; il ne tire de `sandbox/` que `acquisition.ts`, par `ecriture/noms.ts`. La file des demandes, les gestes, les écritures et les lectures paginées restent dans la session. Autorité : `src/nomenclature/calcul.ts` `calculerLeBilanDirect`. Tests : `tests/nomenclatureCalculPur.test.ts` (parité avec la session sur les fixtures et le rejeu), `tests/nomenclatureSandboxQuickjs.test.ts`.
- **Le sandbox confie le calcul du bilan à un Worker de l'écran et se replie sur son propre calcul.** `noms-analyser` : le sandbox lit l'inventaire, envoie `calcul-des-noms` (demande, génération suivante, révision = `reperDesLectures`, `EntreeDuCalcul`) ; l'écran le passe au Worker, source embarquée au build et lancée depuis un `Blob` ; `noms-calcules` ramène le bilan, que le sandbox envoie tel quel à l'écran. Une réponse dont la demande, la génération ou la révision diffère est ignorée, comme celle d'une analyse remplacée. Repli : `indisponible` (Worker impossible), `demarrage` (pas de `demarre` en 5 s, ou script refusé), `echec` (calcul ou message en erreur), `delai` (aucune réponse en 120 s) ; la session mène alors `calculerTout` par tranches. Le Worker n'écrit rien et ne lit pas Figma ; l'écriture relit les objets. Borne : après un bilan du Worker la session ne garde que l'entrée (inventaire, règles) ; la première lecture ou le premier geste refait le calcul complet dans le sandbox, une seule fois (G1c retire ce calcul). Le journal du mode Tokens note `voie`, `repli` et les phases `worker-transfert`, `worker-demarrage`, `worker-calcul`, `worker-retour`. Autorité : `src/nomenclature/session.ts` `calculerAilleurs`, `src/nomenclature/distant.ts` `creerPortDistant`, `src/ui/nomenclature/calculDesNoms.ts` `creerCalculateurDeNoms`. Tests : `tests/nomenclatureCalculDistant.test.ts` (parité, repli, réponse périmée), `tests/calculDesNomsClient.test.ts`, `tests/interface/calculDesNoms.test.mjs` (Chromium, par `test:ui`).
- **La question « même mot ou deux mots ? » est une paire d'indice `ecriture-proche` ; « Termes différents » la range dans les règles du fichier (`distinct:a|b`).** La question ne revient pas, et le plugin n'ajoute aucun couple au dictionnaire du kit. Tests : `tests/nomenclatureSession.test.ts` (E2.2), `tests/nomenclatureQuestions.test.ts`.
- **Le kit repère par sa place la nature d'un segment : composant, élément de composant ou palette (`naturesDesNoms`).** Un tel nom est un seul terme du vocabulaire, n'entre dans aucune question et ne compte jamais dans « Sans règle ». Un remplacement ne coupe jamais un terme (`termesDuSegment`). Un dossier partagé avec une variable protégée garde son nom. Tests : `kit/tests/naturesReferentiel.test.ts`, `kit/tests/termesReferentiel.test.ts`, `kit/tests/lexiqueReferentiel.test.ts`.
- **Une lecture refusée du suivi racine ou de la marque de Palettes n'est pas une absence.** Une variable de couleur dont la protection ne se lit pas n'est ni proposée ni écrite (motif `non-verifiee`), annulation comprise ; l'écran donne la cause que calcule `causeDeProtection` du socle. Tests : `tests/nomenclatureEcriture.test.ts`, `tests/nomenclatureProtocole.test.ts`, `/tests/nomsDePalettes.test.ts`.
- **La liste du vocabulaire a une ligne par terme et par place : groupe (tout segment avant le dernier) ou variable (le dernier).** Chaque ligne s'écrit dans la convention de sa place et ne compte que les noms de cette place ; un composant ou une palette n'a qu'une ligne, aux groupes. La fiche reste une par terme. Tests : `tests/nomenclatureProjection.test.ts`.
- **Le sandbox garde l'inventaire et le résultat et n'envoie à l'écran que le `Bilan` et les pages demandées.** Chaque réponse porte le numéro de sa demande et la génération du calcul ; l'écran ignore une réponse périmée. `appliquer` relit les règles et refuse si elles ont changé depuis le bilan. Borne : après un bilan du Worker, il ne garde que l'entrée du calcul jusqu'à la première lecture ou au premier geste. Tests : `tests/nomenclatureProtocole.test.ts`, `tests/nomenclatureFrontiereUi.test.ts`.
- **Le sandbox n'envoie que des données et des codes.** Les textes destinés au designer vivent dans `src/ui/nomenclature/textes.ts`.
- **Sous le filtre de l'arbre, Appliquer n'écrit que les noms de la collection choisie.** La sélection envoyée n'a aucun groupe ni exclu : chaque nom affiché est un `inclus`. Le pied commun et le compte de l'onglet Constats comptent ces noms. Tant que les pages de `lignes` ne sont pas toutes lues, le pied dit « Chargement des noms… » et Appliquer reste inactif. Borne : sans filtre (recherche en cours, croix de la puce), la sélection est celle des groupes cochés. Autorité : `src/ui/nomenclature/aAppliquer.ts` `appliquer`, `src/ui/nomenclature/renommages.ts`. Tests : `tests/interface/nomenclature.test.mjs`, `tests/cochageCommun.test.ts`.
- **Les constats de structure et les corrections de modes et de scopes viennent du message `structure`, lu à chaque relevé sous une numérotation propre au domaine.** Chaque constat se range dans la section de sa catégorie de l'onglet Constats ; un constat corrigeable y porte sa correction, sous Variables manquantes, Crans, Modes ou Scopes. Toutes les cases arrivent décochées, y compris une ligne ajoutée par une relecture ; « Tout cocher » et « Tout décocher » sont sous la bande de chaque section qui a des cases. Le compte de l'onglet Constats vient de `tokens.total()`, qui compte aussi les cartes hors du DOM : un conteneur de plus de 50 cartes les pose dans une liste virtuelle (`creerHoteDeCartes`, `SEUIL_DE_LISTE`), et les cases cochées vivent dans un ensemble d'identifiants, non dans le DOM. Le repli de Noms au-delà de 20 cartes est une règle distincte. Borne : la puce du filtre de l'arbre se montre sous Constats mais ne restreint que les renommages de Noms, et les corrections de structure ne suivent pas ce filtre ; le sandbox du domaine n'est pas construit, les données viennent de la galerie. Autorité : `src/ui/structure/index.ts` `monterStructure`, `src/ui/virtualisation.ts` `creerHoteDeCartes`. Tests : `tests/interface/structure.test.mjs`, `tests/cochageCommun.test.ts`, `tests/listesDeSections.test.ts`.
- **Appliquer écrit les renommages avant les corrections de structure, et un échec des renommages arrête les corrections.** Le pied commun envoie `appliquer-structure` avec les identifiants cochés au clic, seulement après la réponse `application` et le `bilan` de la relecture. Un refus, une erreur, une confirmation refusée ou une nouvelle lecture des noms n'envoie rien à la structure, et les cases restent cochées. Borne : sans nom coché, seules les corrections partent ; renommages écrits sans correction cochée, le pied envoie `lire-structure` après le `bilan` (`SourceDeStructure.relire`), jamais après un refus, une erreur ou un abandon. Autorité : `src/ui/tokens/cochage.ts` `monterLePied`, `src/ui/nomenclature/suiteDuPied.ts`. Tests : `tests/cochageCommun.test.ts`.
- **Les règles que le mode Composant prépare arrivent à l'interface sous le message `regles-recues` et se rangent en tête de la puce Questions de l'onglet Constats, sous leur intertitre.** Ajouter la règle envoie `remplacer-par` (le terme retiré, le terme voulu) et la carte part avec le bilan qui répond ; Écarter et Plus tard la retirent sans rien envoyer ; le compte de Questions les inclut. Dans un fichier sans variable locale, la library grise Constats (sans compte) et ouvre Règles. Borne : `lire-texte` (`src/sandbox/preparation.ts`) est le seul à produire `regles-recues`, après `preparations`, quand le texte échangé porte des règles ; la session de Nomenclature ne le reçoit pas ; une règle écartée revient avec le message suivant ; un état « rien à faire » du bilan cache les règles reçues. Autorité : `src/ui/nomenclature/reglesRecues.ts`, `src/ui/nomenclature/aTrancher.ts` `monterATrancher`, `src/ui/nomenclature/coquille.ts` `poserLaLibrary`. Tests : `tests/bibliothequeReleve.test.ts`, `tests/interface/nomenclature.test.mjs`.
- **L'onglet Historique de la Configuration classe le journal du dernier renommage avec `src/ecriture/noms.ts` `classerLeRenommage`, la fonction qu'emploie l'annulation.** Même fonction : il annonce avant le clic les noms que l'annulation laissera. Le bilan porte ce classement dans `dernierRenommage` et les règles du dernier import dans `dernierImport`. Tests : `tests/nomenclatureEcriture.test.ts`, `tests/nomenclatureProjection.test.ts`.
- **L’Historique annule la dernière création de variables par `annuler-structure`, et seulement pendant la session qui l’a reçue.** La section « Dernière création de variables » naît d’un message `variables-creees` qui a écrit au moins une variable, avec l’heure de sa réception ; le bouton reste actif tant que `structure-annulee` rend un refus, un journal absent ou illisible, ou des lignes restantes. Borne : aucun message ne relit le journal de structure, donc un rechargement du plugin perd la section ; un seul lot de structure se garde (Q-71). Autorité : `src/ui/nomenclature/configuration.ts` `noterLaCreation`. Tests : `tests/interface/configuration.test.mjs` (par `test:ui`).
