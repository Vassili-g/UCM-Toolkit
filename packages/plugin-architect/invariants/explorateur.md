# Explorateur de tokens

- **Seul `src/ecriture/` modifie le document.** Hors de `src/ecriture/` et de `src/ui/`, aucun fichier n'appelle une création, une suppression, un setter de variable, un import de composant ou de style, `setPluginData`, `setSharedPluginData`, `commitUndo` ni `loadAllPagesAsync`, et aucun ne change la page courante, la sélection ni la vue du designer. Aucun fichier de `src/` hors de `src/ecriture/`, interface comprise, n'importe `template/ecriture` du socle ; `src/ecriture/regles.ts` le fait pour poser l'instance de règles d'un composant. Seules `src/lecture.ts` et `src/ecriture/liaisons.ts` appellent `importVariableByKeyAsync` ; `src/ecriture/selection.ts` est la seule à changer la sélection. Borne : `tests/loiDEcriture.test.ts` lit le texte ligne à ligne. Tests : `tests/loiDEcriture.test.ts` lit les sources, `tests/loiDEcritureDesNoms.test.ts` borne `src/ecriture/noms.ts` ; les doubles de `tests/figmaDeTest.ts` lèvent à toute affectation et à tout appel hors des lectures permises. → [spec](../SPEC.md#lecture-seule)
- **Une liaison s'écrit après relecture, et un lot pose un seul point d'annulation.** `src/ecriture/liaisons.ts` `ecrireLeLot` n'écrit rien, ni liaison ni instance de règles, si le fichier ne déclare plus UCM ; `ecrireLesLiaisons` relit aussi la déclaration, relit pour chaque correction le layer, les valeurs du variant (`aRelire.axes`), la liaison du champ (`aRelire.avant`) et la peinture, puis saute avec un motif ce qui diffère ; `ecrireLeLot` appelle `commitUndo` une fois, après les liaisons et les règles, et jamais sans écriture. `src/sandbox/corrections.ts` n'écrit que les corrections de l'analyse courante non périmée, une opération à la fois, analyse comprise. Borne : un champ qui n'est ni numérique ni une peinture unie est sauté (`fait-faux`). Tests : `tests/ecritureDesLiaisons.test.ts`, `tests/corrections.test.ts`.
- **Le noyau, `modele.ts`, `groupes.ts`, `indexation.ts`, `resolution.ts`, `comparaison.ts` et `diagnostics.ts`, ne lit ni `figma`, ni le DOM, ni une intégration UCM.** Aucune règle hors de `src/integrations/` ne nomme une collection. Un groupe vient des seuls segments `/` du nom Figma et s'identifie par sa collection et ses segments (`cleDeGroupe`). Tests : `tests/loiDEcriture.test.ts` (la même loi), `tests/groupes.test.ts`. → [spec](../SPEC.md#architecture-libre)
- **Un contexte choisit un mode par famille, une collection et ses extensions.** Une famille absente prend le `defaultModeId` de sa collection ; un mode n'est jamais rapproché par son nom d'une collection à l'autre. Un cycle se détecte sur les couples variable–mode du chemin ; une chaîne de plus de `BORNE_DES_ETAPES` étapes est interrompue sans être déclarée cyclique. Tests : `tests/resolution.test.ts`. → [spec](../SPEC.md#résolution)
- **Une cible d'alias que `getVariableByIdAsync` ne rend pas s'importe par la clé que porte son identifiant de bibliothèque (`src/lecture.ts` `cleDeBibliotheque`).** Aucune autre variable n'est importée : ni un identifiant local, ni une variable qu'aucun alias du relevé ne vise. Une cible que l'import ne rend pas non plus reste introuvable, ou refusée quand la lecture a levé ; aucune n'est déclarée supprimée. Borne : au plus `CONCURRENCE` lectures par identifiant sont en vol, une seule par identifiant. Tests : `tests/lecture.test.ts`.
- **Un identifiant de mode désigne une seule collection du relevé.** Plusieurs collections qui déclarent le même identifiant : la collection locale le garde, chaque collection distante le reçoit préfixé du sien. Autorité : `src/lecture.ts` `separerLesModes`. Tests : `tests/lecture.test.ts`. → [§lecture]
- **À la lecture, une variable liée à un calque ne s'importe jamais : seules les cibles de ses alias le peuvent.** `src/lecture.ts` `lireLesVariables` lit chaque départ par `getVariableByIdAsync` seul ; `src/lectureDuComposant.ts` n'appelle aucun import. Borne : une variable de départ que Figma ne rend pas par son identifiant reste introuvable. Tests : `tests/lectureDuComposant.test.ts`, `tests/loiDEcriture.test.ts`. → [§vue]
- **La vue composant ne parcourt aucun calque sous une instance imbriquée.** `src/lectureDuComposant.ts` `lireLeComposant` s'arrête à toute `INSTANCE` strictement sous le sujet, et n'en lit que les liaisons des champs que `InstanceNode.overrides` dit surchargés par le parent, rattachées au calque de l'instance. Tests : `tests/lectureDuComposant.test.ts`. → [§vue]
- **Seuls `src/code.ts` et `src/apercu.ts` appellent `exportAsync`, qui rend des octets en mémoire.** Tests : `tests/loiDEcriture.test.ts` lit les sources ; `tests/apercu.test.ts` tient la borne de 720 px et l'export qui lève.
- **Les modes d'un calque suivent la table de `separerLesModes`.** `src/lecture.ts` `traduireLesModes` la leur applique avant toute résolution de la vue composant : un mode de bibliothèque renommé se rapproche encore du mode du calque. Tests : `tests/lectureDuComposant.test.ts`. → [§lecture]
- **L'interface est sombre quel que soit le thème de l'hôte.** `src/ui/roles.css` précède la feuille du socle ; `styles.css` affecte ses couleurs à chaque rôle. Tests : `tests/stylesUi.test.ts` refuse un rôle oublié et toute lecture de `--figma-color` ; les tests d'interface relisent les fonds sous les deux thèmes. Le panneau latéral du mode Tokens reprend les couleurs de la maquette (`--laterale-*` de `roles.css`, affectées aux rôles sous `.panneau-lateral` seul).
- **Une réponse du sandbox porte le numéro de sa demande.** L'interface ignore celle d'une lecture remplacée (`src/ui/index.ts`). Tests : `tests/interface/interface.test.mjs`.
- **Les intégrations s'activent explicitement et leur absence ne produit aucun constat.** Le profil UCM ne contrôle que les collections que le designer associe à une couche (`src/integrations/profilUcm.ts`). Tests : `tests/integrationsUcm.test.ts`. → [§intégr]
- **Les couches sont celles de `COLLECTIONS`.** `components` vise `theme`, `layout` ou `typography`, `theme` vise `brands` ou `utility`, et `brands`, `utility`, `layout` et `typography` visent `primitives`. Une association rangée sous `brand`, `color-brands`, `color-utilities` ou `layouts` se lit sous le nom courant (`FORMES_ANCIENNES_DES_COLLECTIONS`) ; une sous `usage` se lit sans couche. Tests : `tests/integrationsUcm.test.ts`. → [§intégr]
- **Dans `theme`, chaque variable de dossier porte les portées de `SUPPORT_DES_VARIABLES`, et `scale/*` aucune.** Son alias vise, dans chaque mode, le cran de `TABLE_DES_DOSSIERS` dans le sens que donne `texteDesBoutons` de la recette associée, lu à la fin du nom de la cible (`primary/light/700`). `identity` et `scale/*` ne se jugent pas. Tests : `tests/integrationsUcm.test.ts`. → [§intégr]
- **Les contrats et `tokens.json` se jugent par `@ucm-kit/core/lecteurs/navigateur`, jamais par la porte Node.** Tests : `tests/bundle.test.ts` refuse toute dépendance Node dans les deux bundles ; `kit/tests/porteNavigateur.test.mjs` la tient dans le kit. → [§intégr]
- **Le relevé garde l'espace de couleur du document (`documentColorProfile`, `Releve.espace`).** Les copies, le contraste et l'affichage convertissent en sRGB par `src/espace.ts` `versSrgb`. Une comparaison au token publié (`comparerAuTokenPublie`) ou un contrôle du profil qui n'a pas pu se faire rend une limite avec sa cause ; l'égalité ne s'affiche que si chaque mode annoncé a été comparé. Tests : `tests/vuesDesLimites.test.ts`. → [§intégr]
