# Layout, dimensions et bornes

- **Le node de layout d'un variant s'élit au score, selon la racine d'où part la recherche.** Aucune extraction ne choisit son calque : toutes reçoivent l'élection, `sizes` comprise. Autorité : `layoutNodes.ts`. → [spec](../../../docs/format/FORMAT.md#3-layout)
- **La vue exacte publie ce que l'élection écarte.** Projection de référence : seulement le node élu. Vue exacte, depuis la racine de chaque variant : tout calque de `getAllNodes` reçoit un chemin, en slot ou sous sa feuille. Aucun message ne dit perdu un calque écarté par l'élection. → [spec](../SPEC.md#3-layout)
- **Un auto-layout linéaire publie ses alignements (`justifyContent`, `alignItems`) ; ses slots, seulement leurs exceptions (`alignSelf`, `flexGrow`).** Absence = hors flux ou non applicable, jamais `flex-start` deviné. → [§flux]
- **Le menu de dimensionnement Figma fait autorité, axe par axe ; un axe ne décide jamais de l'autre.** Slot : `Fill` publié, `Fixed` cite une variable dans `size`, absence = `Hug`, figé sans variable : avertit. Composant : `structure.sizing` toujours publié, vocabulaire CSS (`stretch`, `fit-content`), par propriété (`width`, `height`).
- **Sous un auto layout linéaire, un axe `Fixed` que Figma étire se lit `Fill`.** `layoutAlign: STRETCH` (axe secondaire), `layoutGrow: 1` (principal). Figma rend ainsi un enfant masqué réglé `Fill` ; réclamer sa variable contredirait le `alignSelf: stretch` publié. `Hug` reste `Hug`. Borne : racine, enfant absolu, enfant de grille : menu seul. Autorité : `flexLayout.ts` `menuDeDimensionnement` (menu d'un enfant). → [§flux]
- **Une taille de maquette se distingue d'une décision du design system par la liaison, jamais par le fait d'être figé.** Sans variable, largeur fixe = `stretch` ; avec, token publié. Nombre brut : jamais contractuel ; variable liée : toujours, sauf où Figma ne permet pas de lier. Exceptions énumérées : pistes et cellules d'une grille, place d'un calque hors du flux ; pixels sous notice, sans token ni couverture dégradée. → [§dimensions]
- **Un composant sans auto layout fait exception à la taille de maquette.** Ses layers ne donnent aucune taille ; axe figé sans variable : avertit, publie `stretch` (`extractLayout.ts` `warnUntokenizedFreeSize`). → [§dimensions]
- **Sur un tracé (`VECTOR`, `BOOLEAN_OPERATION`, `STAR`, `POLYGON`), la dimension est le dessin.** Aucune variable réclamée ; liée, elle se publie comme ailleurs. Borne : `RECTANGLE`, `ELLIPSE`, `LINE` exclus, formes que la règle « le type du node ne tranche pas » vise nommément.
- **Un calque hors du flux est placé.** `constraints` : bords d'accroche ; `inset` : distance en pixels, une seule signification par clé. Côtés publiés = ceux de l'accroche, les deux d'un axe sous `stretch`, `center`, `scale`. Calcul par le centre. Géométrie absente : rien publié. Même placement pour un enfant de cadre, composant ou instance sans auto layout ; pas pour un enfant de groupe. Autorité : `flexLayout.ts` `estPlaceParSesContraintes`. → [§position]
- **Un axe en `stretch` ou en `scale` n'a pas de dimension propre.** `fixedDimensions` ne le compte pas comme figé ; aucune variable réclamée. → [§position]
- **La `rotation` d'un calque publié est écrite en convention CSS, absente sous le centième de degré.** Notice sur le seul écart restant : dans un auto layout, Figma espace les voisins d'après la boîte tournée, CSS d'après la boîte droite. Autorité : `flexLayout.rotationDegrees`.
- **`bounds` publie les bornes du composant et de chaque slot, indépendamment du menu de dimensionnement, à la règle commune.** Geste : nommer la borne, jamais la retirer. Calque intermédiaire : pas propriétaire, avertit. → [§dimensions]
- **Une valeur uniforme est valide seulement si tout le groupe requis est lié.** Côtés d'un champ à variables différentes : détail publié (`padding.x`, `padding.y`, `radius`, largeur d'un stroke) ; forme courte s'ils la partagent. Groupe par côté : partiel permis si les côtés absents valent zéro ; côté fixe non neutre : avertit. Taille d'un slot : pas un groupe par côté, variable unique. Élection du node de layout : compte seulement `hasCompleteBinding`.
- **`wrap` est une propriété de flux, au niveau haut même sous `sizes`.** `rowGap` : token à la règle commune ; absence sous `wrap` = `gap`. → [spec](../../../docs/format/FORMAT.md#passage-à-la-ligne)
- **Une propriété Figma qu'aucun champ du schéma ne porte avertit au lieu de disparaître.** `layout` reste publié (sa forme l'exige) ; son repli `flex-row` se signale.
- **Une propriété à effet visuel qu'aucun champ du schéma n'écrit avertit, seulement sur un calque publié et jamais pour une valeur au défaut de Figma.** Première réserve : le masque d'une icône (ce relevé n'en voit jamais les tracés). Seconde : `clipsContent`, `listSpacing` nul. Aucune réserve sur l'usage supposé d'un calque : sur un calque publié, `isMask` avertit comme le reste. Une propriété écrite par le contrat n'y figure jamais, `rotation`, `opacity`, alignement et casse d'un texte compris. → [§non-portables]
- **Soulignement et `openTypeFeatures` (défauts non documentés par Figma) : la valeur neutre est celle que CSS rend sans déclaration.** → [§non-portables]
- **`opacity` cite sa variable.** Dépendance : la porte seulement si son instance diffère de son composant principal. Autorité : `nodeBindings.ts` `resolveOpacity`, unique lecture. → [spec](../../../docs/format/FORMAT.md#opacité)
- **Un effet se publie par son effect style, jamais par le calque.** `effectStyles` lit les liaisons sur `style.effects[i]` ; usage situé par un chemin de slots (`[]` pour la racine). Relevés : calques publiés d'une vue exacte seulement ; une dépendance garde ses effets pour son contrat. Avertissent : effet sans style, style introuvable ou dont le calque s'écarte, champ sans variable, effet que le contrat n'écrit pas. `effects` suit l'ordre de CSS, traduit de celui de Figma. Autorité : `effectStyles.ts` `ordreCss`. → [spec](../../../docs/format/FORMAT.md#effets)
