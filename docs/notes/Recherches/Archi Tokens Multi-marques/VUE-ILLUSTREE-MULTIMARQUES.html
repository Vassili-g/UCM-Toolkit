Architecture des tokens multi-marques

Les collections séparent les palettes, la marque et le thème. Les composants utilisent des rôles de couleur communs, en clair comme en sombre.

La logique des collections

Une couleur est définie dans primitives. Les collections suivantes la désignent par alias : changer une palette ou une marque conserve les noms utilisés par les composants.

1. Définir les valeurs

primitives contient les palettes nommées et leurs crans, séparés en light et dark. Les statuts disposent des intensités soft et vivid. Les dimensions et les valeurs typographiques y sont aussi définies.

2. Affecter les palettes

color-brands affecte une palette à primary et à secondary dans chaque mode de marque. identity expose les couleurs de charte. color-utilities affecte les palettes communes : neutre, statuts et niveaux d’élévation.

3. Choisir le thème

theme expose les rôles solid, surface, page et ring. Ses modes light et dark choisissent les alias adaptés. La marque se règle séparément dans color-brands.

4. Relier les composants

components nomme les propriétés des composants. Leurs couleurs utilisent les rôles de theme ; layouts et typography regroupent les dimensions et les réglages de texte par alias vers primitives.

Pour retrouver la valeur d’un rôle de marque, suivre ses alias :

components→theme→color-brands→primitives
CollectionAlias permis versPortées Figma

Un statut ou le neutre passe par color-utilities à la place de color-brands. scale expose les crans pour les besoins que les rôles ne couvrent pas.

Le panneau des variables

Choisir une collection, puis déplier ses dossiers. Chaque colonne représente un mode. Cliquer sur un alias ouvre la variable visée ; sa pastille montre la couleur résolue dans le contexte de la colonne. Hors de leur collection, les aperçus utilisent le thème clair et la première marque.

Le panneau présente un instantané des variables de référence. Le générateur actualise ses données depuis un export tokens.json, sans recalculer les palettes ni modifier les alias.

Un tiret signale une variable qui ne vise aucun cran de la table : son libellé dit ce qu’elle porte. Les valeurs de elevation se lisent dans le panneau, collection theme.

  • Choisir le dossier selon le fond derrière le texte. La page ou la carte : page. Une teinte claire : surface. Une couleur forte : solid.
  • Un état change le fond, jamais le texte : surface/foreground sur surface/hover.
  • Une alerte et un badge discret prennent surface/default et surface/foreground ; un bouton teinté les trois états de surface ; un contour discret page/divider, un contour franc surface/border. Le texte courant d’une alerte, coloré ou neutre, est un choix du composant.

Recommandations de design

Ces conseils d’implémentation ne changent pas le contrat d’un composant.

    Le bouton basculable

    Un bouton basculable change de dossier selon son état. Chaque état garde le texte de son dossier.

    ÉtatFond au reposAu survolÀ l’appuiTexte et icône

    Le focus ajoute ring. Un bouton indisponible utilise disabled/* : cet état se distingue du bouton non activé, qui reste cliquable. Cette composition utilise les variables existantes.

    Utiliser et vérifier les tokens

    Dans Figma, régler la marque dans color-brands et le thème dans theme. Un cadre peut changer de thème tout en gardant la marque de son parent. À l’ajout d’une marque, renseigner chaque alias de sa colonne.

    Un calque utilise theme ou components pour ses couleurs. Les collections intermédiaires de couleur ont des portées vides ; les portées de theme suivent ce que chaque variable peint.

    Côté code, ucm tokens css produit les propriétés CSS et les sélecteurs des axes. Les attributs par défaut sont data-color-brands et data-theme. Le champ modes de ucm.config.json peut renommer l’attribut de marque.

    OutilRôle

    La table et les garanties sont définies dans dossiers.ts et garanties.ts. Les contrastes se mesurent sur les couleurs calculées ; le numéro d’un cran ne suffit pas à prouver un seuil.
