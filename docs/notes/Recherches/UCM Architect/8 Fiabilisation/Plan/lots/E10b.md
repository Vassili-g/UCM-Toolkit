Par case :

- E10.4. Le code d'un point se lit sur son titre sans les noms entre « » (N-67) : « masqué », « pilote » et « Variable introuvable » écrits par le designer ne changent plus le code. C34 garde les combinaisons manquantes et les états non reconnus ou tolérés ; « aucun variant » est un C42 bloquant ; « aucune propriété définie » et les collisions de noms sont des C42 à vérifier. Un point C30 ou C41 prend la famille de ce qu'il lie : tailles (marge, espacement, rayon, épaisseur de contour, dimensions minimales), typographie (style de texte), tokens (opacité, effet), liaisons (remplissage, contour). Le panneau le range dans l'élément de cette famille (test par `elementDuConstat`).
- E10.6. L'empreinte porte le titre, les nœuds et les éléments ; un point sans élément garde son identifiant d'avant. Deux points distincts n'ont aucun suffixe de rang. Deux phrases que cela ne distingue pas prennent un rang dans l'ordre de leur texte, donc le même d'un ordre à l'autre.
- E10.7. N-84 : l'ordre des phrases jumelles ne change plus l'identifiant ; Ig-15 à Ig-17 du harnais F9 sont sans écart.
- E5.8. `sansLesDoublonsDuMoteur` retire, après le calcul des corrections, le C30 dont le layer et le champ sont portés par un C25 ou un C29. Le champ se lit dans le titre du point (noms Figma ou libellés du moteur : `padding`, `gap`, `stroke weight`, `fill`, `stroke`, `cornerRadius`). Le retrait précède Ignorer : un constat du kit ignoré garde le C30 silencieux. Un autre layer, un autre champ ou l'opacité gardent leur C30.
- E10.N08. `controlerCouchesParEtapes` ne rend plus C20 pour l'alias d'un token de `components` vers un `brands` à segment de mode quand `contournementsDuTheme` rend C63 `theme` pour le même couple. Décisions prises :

- Les points `proprietes` que la table ne reconnaît pas (par exemple la visibilité d'un calque tenue par un composant) tombent dans la règle du point inconnu, C42 à vérifier, au lieu de C34.
