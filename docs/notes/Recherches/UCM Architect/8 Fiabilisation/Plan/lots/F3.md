## Marche à suivre

Une séance d'une demi-heure, en trois parties. La conversation principale construit le plugin avant la séance et donne le dossier à
importer. Chaque rapport téléchargé va dans `_local/recette-f3/`, sous le nom donné ici.

Partie 1, mode Tokens, sur le fichier de 2 415 variables.

1. Ouvrez Architect, mode Tokens, et cliquez Analyser. Attendez la fin du rendu des constats.
2. Cliquez Actualiser, sans rien changer au fichier. Attendez la fin du rendu.
3. Cliquez « Télécharger le rapport d'analyse ». Rangez le fichier sous `tokens.json`. Il porte le journal des phases (G4.3, E15, G5).
4. Regardez l'écran une fois : deux onglets Constats et Règles, catégories repliables avec leur icône, cases décochées. Notez tout écart
   avec la section 1 de la maquette.
5. Renommez une variable `…/border` en `…/bordr`, puis cliquez Actualiser. Une question propose `border`, sans case cochée. Annulez le
   renommage avec Ctrl+Z.

Partie 2, mode Composant (E12.3).

6. Sélectionnez le composant Alert, cliquez Analyser, puis « Télécharger le rapport d'analyse ». Rangez-le sous `alert.json`.
7. Même geste sur Input. Rangez-le sous `input.json`.

Partie 3, mode Composant, sur Button.

8. Analysez Button. Les corrections arrivent décochées (section 2). Cliquez Ignorer sur une carte : elle passe dans les ignorés.
9. Changez une couleur de Button sans cliquer Actualiser. Le bandeau d'analyse périmée apparaît (section 4). Annulez avec Ctrl+Z.

Notez pour chaque étape « conforme » ou l'écart vu. Les sections 5 à 7 de la maquette (tous ignorés, analyse partielle, demande
refusée) se voient dans la galerie, sans Figma.
