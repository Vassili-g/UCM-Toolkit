Correctif 2 (décision du mainteneur). Une correction de scope ou d'alias de mode ne s'écrit pas si le nom de sa variable a changé entre la lecture et l'écriture. `src/sandbox/structure.ts` lit le nom (`faits.variable` du constat qui porte la correction) dans `nomsLues` et le passe à `Acces.ecrire(corrections, nomsLus)` ; `src/ecriture/structure.ts` (`OptionsDeStructure.nomsLus`, `planifier`) saute la correction en `objet-change` quand la variable porte un autre nom ou que la table n'a pas son identifiant. Sans `nomsLus`, le nom n'est pas vérifié. Le motif est `objet-change`, non `fait-faux` : `fait-faux` dit que les scopes ou l'alias ont changé, et `objet-change` est celui d'une variable qui n'est plus l'objet lu. La relecture qui suit propose la correction de nouveau si elle tient. Régressions dans `tests/relectureApresAppliquer.test.ts` : le test D4b « renommage puis correction dans le même Appliquer » attendait deux corrections écrites ; il attend maintenant une écrite et une sautée, et deux tests s'y ajoutent (renommage d'une variable à scope, correction sans renommage qui s'écrit). Sans le correctif, deux de ces tests échouent (vérifié). Le double `acces.ecrire` du banc de test passe `nomsLus`.
