# E16. Fautes de 3 lettres, noms de composant et synonymes UCM

Phase E. Lire avant de commencer les règles d'exécution, les chemins et commandes et l'introduction de la phase E
dans [README.md](../README.md), puis l'« Avancement » de [E14](E14.md) et de [E15](E15.md).

Agent : `implementeur-exigeant`. Dépend de : E15.

Le rejeu de Slice après E15 laisse 25 mutations muettes. Le mainteneur a tranché chaque groupe, et deux questions de E14.

- Une faute dans un nom de composant que le kit connaît (`btton`, `buttono` pour `button`) donne une question de faute.
- Une faute de 3 lettres devient une faute quand le kit la détecte avec certitude (`tex` pour `text`, `gao` pour `gap`). Un mot de
  2 lettres n'est jamais une faute.
- Une faute qui forme un vrai mot (`neural`, `boy`) reste muette.
- Deux termes UCM synonymes dans le même fichier (`error` et `danger`, `separator` et `divider`) donnent une question qui demande au
  designer de choisir. Ce n'est jamais une correction.
- Q-E14-1 : `status` n'a pas le sens de `state`. `etat`, `état` et `states` se renomment en `state`, dans une variable comme dans une
  propriété de variant. `status` sort des formes tolérées de `state` (`vocabulaire.ts`) et reste un mot à part.
- Q-E14-5 : un pluriel d'abréviation ou de terme composé (`bgs`, `focus-rings`) donne la même question de pluriel que les autres termes.
