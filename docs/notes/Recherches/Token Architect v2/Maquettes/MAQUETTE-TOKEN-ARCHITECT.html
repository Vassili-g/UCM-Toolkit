UCM Token Architect

Ces maquettes dessinent les fonctions du plan d'implémentation. Chaque fenêtre part des écrans réels de l'explorateur et de Nomenclature, figés depuis leurs galeries sombres. Les éléments nouveaux emploient les classes de ces deux plugins et la feuille architect.css. Une pastille rose numérotée marque chaque changement. La légende de même numéro, sous la fenêtre, dit ce qu’il montre. Cette version applique la revue UX ; la section 10 dit ce qu'elle a changé.

1 · Le langage visuel commun

Chaque plugin signale aujourd'hui ses données, ses changements et ses constats avec ses propres formes. Palettes range ses constats en bloquant, alerte, notice et promesse. L'exporteur a une pastille danger. Nomenclature a six pastilles d'état, des jetons et une ligne de réussite. L'explorateur écrit ses chemins dans une autre police. Le socle ne partage que les rôles de couleur, les boutons, les onglets et la feuille.

La proposition : un seul langage visuel pour tous les plugins. Le kit en porte le vocabulaire. Le socle en porte les styles et les composants. Un plugin n'en redéfinit aucun. Token Architect l'emploie le premier.

2 · Le parcours

Le plugin s'ouvre dans le mode qui correspond au fichier. Un fichier de tokens ouvre le mode Tokens. Une sélection de composant ouvre le mode Composant. La bascule de la barre change de mode.

Mode Tokens

Dans le fichier des tokens

  1. L'arbre et la table montrent les variables, dans les modes choisis.
  2. Renommages applique les noms sûrs.
  3. Questions demande les choix.
  4. Règles montre l'écriture et le vocabulaire.
  5. Structure signale les erreurs des alias et des portées.
  6. Un clic sur une variable ouvre sa fiche.
  7. Un plan de génération ou une règle reçue attend en tête de la barre.

Mode Composant

Dans le fichier des composants

  1. Le designer sélectionne un composant.
  2. Analyser lit tous ses variants.
  3. Corrections applique les liaisons sûres.
  4. Questions demande les choix.
  5. À faire dans Figma liste le reste.
  6. Un clic sur un constat sélectionne le calque dans Figma.
  7. Ctrl+Z défait une correction ; Actualiser relit le composant.

Génération des tokens

Entre les deux fichiers

  1. Composant sans tokens : Préparer les tokens.
  2. Répondre aux questions, puis Préparer.
  3. Fichier des tokens : le plan attend. Créer.
  4. Publier la bibliothèque.
  5. Fichier des composants : Analyser. Corrections propose les liaisons.
  6. L'Historique annule une création.

4 · Mode Tokens

La fenêtre passe à 1360 × 800. L'arbre et la table restent à gauche. La barre latérale de 640 px, la largeur de Nomenclature, l'affiche. L'inspecteur devient une feuille, comme la fiche d'un terme.

4a · Renommages, filtrés par l'arbre

Tokens · Renommages
  1. La barre du haut porte le nom UCM Token Architect et le bouton Configuration.
  2. Les onglets de l'explorateur disparaissent. La table montre les variables.
  3. « Modes affichés » remplace le contexte de l'ancien onglet Comparer.
  4. La barre latérale reprend Nomenclature, sans son en-tête.
  5. Un quatrième onglet, Structure, rejoint Renommages, Questions et Règles.
  6. Une collection choisie dans l'arbre filtre la liste. Le bandeau le dit.
  7. Appliquer écrit seulement les noms affichés. Le pied compte ceux-là.
  8. À 640 px, Nomenclature garde ses deux colonnes Aujourd'hui et Après l'application, comme au tour 3.

4b · Questions, et un terme choisi dans Règles

Tokens · Questions
  1. L'onglet Questions ne change pas.
  2. La question ouverte marque ses variables dans la table.
Tokens · Terme choisi dans Règles
  1. Un clic sur un terme ouvre sa fiche.
  2. La table ne montre plus que les variables qui emploient ce terme.
  3. Le bandeau au-dessus de la table rend la liste entière.

4c · Structure

Tokens · Structure
  1. L'onglet reprend les diagnostics de l'explorateur et les quatre règles du profil UCM.
  2. Les constats se rangent par sujet : chaînes, modes, valeurs, couches, portées.
  3. Chaque carte garde la forme de Nomenclature. Une carte ouverte propose « Ouvrir la fiche ».
  4. Seules les portées se corrigent ici. Leur carte a une case.
  5. Appliquer range la correction dans l'Historique.

4d · La fiche d'une variable

Tokens · Fiche d'une variable
  1. Un clic sur un nom de la table ouvre la fiche. La ligne reste marquée.
  2. La fiche reprend la feuille d'un terme de Nomenclature.
  3. Le titre colore les groupes en orchidée et la variable en olive.
  4. La valeur se lit dans les modes affichés par la table. La fiche les nomme.
  5. « Comparer avec » remplace l'onglet Comparer. « Utilisée par » remplace l'onglet Dépendants.
  6. « Renommages de cette variable » relie la fiche à Nomenclature.

4e · Bibliothèque, règle reçue, fichier hors UCM

Tokens · Bibliothèque lue depuis le fichier des composants
  1. Les noms s'affichent tout de suite. Les valeurs d'un groupe se chargent à son ouverture.
  2. Renommages, Questions et Structure sont grisés. Ils ne peuvent rien écrire ici.
  3. Règles reste ouvert.
Tokens · Règle reçue du mode Composant
  1. Une règle préparée depuis un composant attend en tête de la barre.
  2. « Ajouter la règle » l'ajoute aux Règles. Renommages propose ensuite les noms.
Tokens · Fichier hors UCM
  1. L'arbre, la table et les fiches restent.
  2. La barre latérale invite à déclarer l'architecture (question M-10).

5 · Mode Composant

La fenêtre passe à 1040 × 760. La vue Composant garde 400 px à gauche. La barre latérale de 640 px montre l'analyse. Le composant d'exemple est Alert, avec 11 variants : 4 statuts × 3 styles, sans warning · filled.

5a · Avant la première analyse

Composant · Pas encore analysé
  1. La sélection d'un composant ne lance rien.
  2. Le bouton principal de la barre dit Analyser. Après la première analyse, il dit Actualiser.
  3. La phrase dit ce que l'analyse lit.

5b · Corrections

Composant · Corrections
  1. Chaque constat est dans un seul onglet, selon la façon dont il se règle.
  2. Le panneau s'ouvre sur le premier onglet qui a du contenu.
  3. L'onglet reprend le tour 3 de Renommages : cartes cochées, la règle en jetons ou en phrase, les deux colonnes Aujourd'hui et Après l'application, le pied Appliquer.
  4. La ligne grise de la carte nomme le variant et les calques. Chaque ligne dépliée donne le token d'aujourd'hui et celui d'après.
  5. La création des règles d'usage est une correction comme les autres. Ctrl+Z la défait.

5c · Un constat cliqué

Composant · Constat cliqué
  1. Un clic sur l'en-tête sélectionne le calque dans Figma et ouvre la carte.
  2. Un constat groupé sélectionne tous ses calques.
  3. L'aperçu de gauche entoure le calque et passe sur son variant.
  4. La carte ouverte donne les faits lus : calque, champ, variable liée, variable attendue, règle.
  5. « Ignorer ces 2 calques » range le choix dans le fichier. Toute l'équipe le voit.

5d · Servir de modèle

Composant · Propagation depuis un variant
  1. Le designer choisit un variant juste dans la matrice, puis « Servir de modèle ».
  2. Corrections reçoit une carte : les liaisons des 10 autres variants, calculées depuis le modèle.
  3. Seules les liaisons exactes sont cochées. Les cas à deux candidats partent dans Questions.

5e · Questions

Composant · Questions
  1. Les cartes reprennent le tour 3 de Questions : la question est la proposition, un seul bouton bordé, les autres réponses en texte.
  2. Le rouge marque ce qui part, le vert ce qui arrive, comme dans Nomenclature.
  3. La proposition est le candidat le mieux rangé par la structure de son nom. Rien n'est écrit avant la réponse.
  4. Renommer une valeur prévient que les développeurs devront modifier leur code.
  5. Un contour sans token renvoie à la génération des tokens.
Composant · Question tranchée
  1. Une réponse fait passer la liaison dans Corrections, cochée.
  2. Rien n'est écrit avant Appliquer.

5f · À faire dans Figma

Composant · À faire dans Figma
  1. L'onglet liste ce que le plugin ne corrige pas. Chaque constat dit où le régler.
  2. Les intertitres reprennent les familles de l'exporteur, plus Tokens, Contraste et Typographie.
  3. Un message de l'exporteur garde son texte, précédé de « Message de l'exporteur ».
  4. Les constats ignorés passent en bas, grisés, avec « Ne plus ignorer ».

5g · Après Appliquer, après Ctrl+Z, vue repliée

Composant · Après Appliquer
  1. La ligne verte reprend Renommages. Elle dit que Ctrl+Z défait le lot.
  2. Le bandeau dit que l'analyse est périmée. Les compteurs passent en gris.
  3. Un seul Actualiser, dans la barre.
Composant · Après un Ctrl+Z
  1. Le plugin voit que le composant a changé. Le même bandeau le dit.
Composant · Vue repliée · 640 × 760
  1. « Replier » ne garde que la barre latérale.
  2. Le canevas reste visible pour voir le calque sélectionné.

6 · Contraste et accessibilité

Les contrôles d'état demandent un composant interactif. Ils sont montrés sur Button, qui a les axes Style, Palette, State et Size. La galerie n'a pas d'état de Button : seule la barre latérale est dessinée.

Alert · Contraste
  1. Chaque mesure montre la paire, le rapport et le seuil.
  2. Une ligne par marque et par thème.
  3. Un fond en dégradé dit que la mesure n'a pas pu se faire.
Button · Accessibilité
  1. Contour et anneau sont mesurés à 3:1.
  2. Les variants désactivés ne sont pas mesurés. Une ligne le dit.
  3. La zone cliquable se compare à 24 px, puis à 44 px en recommandation.
  4. Un texte sous 12 px reçoit une recommandation.
  5. Une ligne rappelle que la mesure porte sur le dessin Figma.
Button · Corrections d'état
  1. Le survol lié au token du repos se corrige par le token frère.
  2. Le dossier change entre deux états : la carte le montre.

7 · Génération des tokens

Le parcours de l'aperçu de génération, sur Tag. Ses couleurs n'ont pas de token. Le parcours passe du fichier des composants au fichier des tokens, puis revient.

7a · Composant : Tag sans tokens
  1. Un composant sans tokens propres reçoit « Préparer les tokens » dans son résumé.
7b · Composant : préparer
  1. La feuille pose les questions. Aucune réponse n'est cochée.
  2. Chaque choix montre la couleur du thème qu'il donnerait.
  3. Les tailles se lient seules quand la valeur existe dans layout. Sinon une question.
  4. Préparer reste inactif tant qu'une question reste.
7c · Composant : plan prêt
  1. Le bandeau dit où continuer et que le plan reste sur ce poste.
  2. La copie en texte n'apparaît qu'ici, quand le plan est complet.
7d · Tokens : créer
  1. Le plan attend en tête de la barre.
  2. Une variable qui existe déjà avec une autre cible le dit.
  3. Le pied tient sur une ligne. « Abandonner le plan » demande une confirmation.
7e · Tokens : après Créer
  1. La ligne verte dit de publier la bibliothèque, puis de revenir au composant.
7f · Composant : lier
  1. Après la publication, Analyser trouve les variables du plan.
  2. Les comptes parlent de liaisons seulement.
  3. Une variable pas encore publiée laisse sa ligne en attente.

8 · Configuration

Une seule Configuration pour le plugin. Elle s'ouvre en page entière sous la barre commune. Retour rend la vue de travail.

Configuration · Réglages
  1. Les sections de Nomenclature ne changent pas. L'aide de la déclaration UCM dit ce qu'elle active.
  2. « Bibliothèque de tokens » dit laquelle le mode Composant lit, et pourquoi.
  3. « Accessibilité » choisit AA ou AAA.
  4. « Plan reçu » colle un plan envoyé en texte.
Configuration · Historique
  1. L'Historique garde la dernière écriture de chaque sorte sur les variables, avec son heure.
  2. Annuler une création prévient que les calques liés perdront leur liaison après publication.
  3. Les corrections d'un composant se défont par Ctrl+Z.
