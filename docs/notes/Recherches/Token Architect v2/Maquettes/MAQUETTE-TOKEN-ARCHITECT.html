UCM Token Architect

Ces maquettes dessinent les fonctions du plan d'implémentation. Chaque fenêtre part des écrans réels de l'explorateur et de Nomenclature, figés depuis leurs galeries sombres. Les éléments nouveaux emploient les classes de ces deux plugins et la feuille architect.css. Une pastille rose numérotée marque chaque changement. La légende de même numéro, sous la fenêtre, dit ce qu’il montre.

Cette version applique la recette du mainteneur du 22 octobre. Ce qu'elle ne commente pas est validé. La marque Modifié signale chaque écran changé depuis. Trois règles valent pour tous les écrans sans être marquées : les termes de Figma et d'UCM restent en anglais, un variant s'écrit comme Figma le nomme (Severity=info, Variant=standard), et la table s'appelle le tableau des tokens.

1 · Le langage visuel commun

Chaque plugin signale aujourd'hui ses données, ses changements et ses constats avec ses propres formes. La proposition : un seul langage visuel pour tous les plugins. Le kit en porte le vocabulaire. Le socle en porte les styles et les composants. Un plugin n'en redéfinit aucun. Token Architect l'emploie le premier.

Deux règles le tiennent sobre. Un chemin reste gris tant que l'écran n'a rien à en montrer. Une couleur dit toujours la même chose, d'un plugin à l'autre.

2 · Le parcours

Le plugin s'ouvre dans le mode qui correspond au fichier. Un fichier de tokens ouvre le mode Tokens. Une sélection de composant ouvre le mode Composant. La bascule de la barre change de mode. Les deux modes ont les mêmes onglets : Corrections, Questions et À faire dans Figma. Le mode Tokens y ajoute Règles.

Mode Tokens

Dans le fichier des tokens

  1. L'arbre et le tableau des tokens montrent les variables, dans les modes choisis.
  2. Corrections applique les noms sûrs, les scopes et les modes.
  3. Questions demande les choix, dont les règles reçues du mode Composant.
  4. À faire dans Figma liste ce que le plugin n'écrit pas.
  5. Règles montre l'écriture et le vocabulaire.
  6. Un clic sur une variable ouvre sa fiche.

Mode Composant

Dans le fichier des composants

  1. Le designer sélectionne un composant. La vue Composant le montre.
  2. Analyser lit tous ses variants.
  3. Le bouton Résultats ouvre le panneau. Sa pastille compte les constats.
  4. Corrections applique les liaisons sûres.
  5. Questions demande les choix.
  6. À faire dans Figma liste le reste.
  7. Un clic sur un constat sélectionne le layer dans Figma.
  8. Ctrl+Z défait une correction. Actualiser relit le composant.

Préparation des tokens

Entre les deux fichiers

  1. Composant sans tokens : Préparer les tokens.
  2. Répondre aux questions, puis Préparer.
  3. Fichier des tokens : les variables préparées attendent. Créer.
  4. Publier la library : Assets, Libraries, Publish.
  5. Fichier des composants : Actualiser. Corrections propose les liaisons.
  6. L'Historique annule une création.

4 · Mode Tokens

La fenêtre passe à 1360 × 800. L'arbre et le tableau des tokens restent à gauche. La barre latérale de 640 px, la largeur de Nomenclature, l'affiche. Le fichier d'exemple est en cours de passage à UCM : sa collection Interface deviendra components.

4a · Corrections, filtrées par l'arbre

Tokens · CorrectionsModifié
  1. Le tableau des tokens montre toujours les renommages cochés. Le nom reste entier. Seul le terme nouveau est vert.
  2. Un clic sur un terme vert ouvre sa carte dans Corrections. La carte s'ouvre et prend une bordure et un fond bleus.
  3. La collection choisie dans l'arbre filtre la barre latérale. Une puce le montre. Sa croix enlève le filtre.
  4. Le bouton à droite de Collections replie toutes les sections de l'arbre, sauf celle qui est choisie.

4b · Questions, et un terme filtré depuis Règles

Tokens · QuestionsModifié
  1. Ouvrir une question ne change pas le tableau des tokens.
  2. « Voir les 2 variables » écrit backgrond dans la recherche de l'arbre, comme une recherche tapée.
  3. Dans chaque nom, le terme de la question est en rose. C'est un groupe.

Réponse

« Un comportement générique comme une recherche normale, sans tag ? Sauf si c'est important d'afficher le type d'élément recherché. »

Oui, le texte seul suffit pour une question. Une recherche de backgrond donne les mêmes variables que la question. Le lien écrit donc le terme dans le champ, sans puce.

Deux filtres ne se disent pas en un mot. Un terme et ses variantes (background, bg, back), et les variables qui visent une variable. Le champ reçoit alors un préfixe : terme:background, vise:Card/bg/default. Le champ reste du texte. Le designer peut taper ce préfixe lui-même ou l'effacer.

Tokens · Terme filtré depuis RèglesModifié
  1. Un clic sur un terme ouvre sa fiche. Le tableau des tokens ne change pas.
  2. « Filtrer le tableau des tokens » écrit terme:background dans la recherche.
  3. Le tableau montre les variables qui emploient le terme ou une de ses variantes.

4c · À faire dans Figma, et les scopes dans Corrections

Tokens · À faire dans FigmaModifié
  1. Un chemin cité dans une phrase prend un fond gris discret. Le mot « vise » se lit comme du texte.
  2. Les gestes renvoient à la fenêtre Variables de Figma.
Tokens · Corrections, modes et scopesRefait
  1. L'écran emploie les mots de l'onglet Scope de la fenêtre Edit variable : Show in all, Frame fill, Shape fill, Text fill, Stroke, Effects.
  2. La tête de la carte dit le changement : quel scope, pour quelles variables.
  3. La ligne grise dit pourquoi : UCM réserve le dossier surface aux fonds.
  4. Chaque ligne montre les cases de Scope cochées, avant et après.

4d · La fiche d'une variable

Tokens · Fiche d'une variableModifié
  1. « Afficher ces 3 variables dans le tableau des tokens » écrit vise:Card/bg/default dans la recherche.

4e · Library, règles reçues, fichier hors UCM

Tokens · Library lue depuis le fichier des composants
Tokens · Règles reçues du mode ComposantRefait
  1. Les règles reçues se rangent dans Questions, sous leur intertitre. Une règle de plus ajoute une carte. Le reste de l'interface ne bouge pas.
  2. Chaque carte reprend la forme d'une question : la règle, son exemple, Ajouter ou Écarter.
  3. Une règle ajoutée rejoint Règles. Corrections propose ensuite les noms.

5 · Mode Composant

La fenêtre s'ouvre à 520 × 760 sur la vue Composant seule. Le bouton Résultats ouvre le panneau des résultats : la fenêtre passe à 1040 × 760. La frontière entre la vue et le panneau se tire à la souris. Le composant d'exemple est Alert, avec 11 variants : 4 valeurs de Severity × 3 valeurs de Variant, sans Severity=warning, Variant=filled.

5a · Avant la première analyse

Composant · Pas encore analyséModifié
  1. Analyser lance la lecture. Après la première analyse, le bouton dit Actualiser.
  2. Le bouton Résultats ouvre ou ferme le panneau. Il porte l'icône du panneau. Avant l'analyse, il n'a pas de pastille.

5b · La section Variants

Trois formes, dessinées sur trois composants : Alert (11 variants, 2 properties), Button (216 variants, 4 properties) et Input (720 variants, 4 properties, dont Type à 12 valeurs).

  • A · Puces : chaque valeur est une puce, avec le constat le plus grave de ses variants.
  • B · Liste : les variants qui ont des constats, du plus grave au moins grave.
  • C · Puces utiles : la valeur affichée et les valeurs qui ont des constats. Les autres passent sous « +N ».
