UCM Token Architect

Ces maquettes dessinent toutes les fonctions du plan d'implémentation. Chaque fenêtre part des écrans réels de l'explorateur et de Nomenclature, figés depuis leurs galeries sombres. Les éléments nouveaux emploient les classes de ces deux plugins et la feuille architect.css. Les repères roses montrent ce qui change.

1 · Le parcours

Le plugin s'ouvre dans le mode qui correspond au fichier. Un fichier de tokens ouvre le mode Tokens. Une sélection de composant ouvre le mode Composant. La bascule de la barre change de mode à tout moment.

Mode Tokens

Dans le fichier des tokens

  1. L'arbre et la table montrent les variables.
  2. Renommages applique les noms sûrs.
  3. Questions demande les choix.
  4. Règles montre l'écriture et le vocabulaire.
  5. Structure signale les erreurs des alias et des portées.
  6. Un clic sur une variable ouvre sa fiche.
  7. Un plan de génération attend en tête de la barre.

Mode Composant

Dans le fichier des composants

  1. Le designer sélectionne un composant.
  2. Actualiser lance l'analyse de tous les variants.
  3. Constats liste tout ce qui ne va pas.
  4. Corrections applique les liaisons sûres.
  5. Questions demande les choix.
  6. Un clic sur un constat sélectionne le calque dans Figma.
  7. Ctrl+Z défait une correction.

Génération des tokens

Entre les deux fichiers

  1. Composant : Préparer les tokens, répondre aux questions.
  2. Le plan reste dans la mémoire du plugin.
  3. Tokens : le plan attend en tête de la barre.
  4. Créer, puis publier la bibliothèque.
  5. Composant : Corrections propose de lier les calques.
  6. L'Historique annule une création.

2 · Aujourd'hui

Les trois écrans réels dont part Token Architect.

UCM Token Explorer, mode Tokens · 1200 × 800
UCM Nomenclature · 640 × 720
UCM Token Explorer, mode Composant · 364 × 724

3 · Mode Tokens

La fenêtre garde 1200 × 800. L'arbre et la table restent à gauche. La barre latérale de 440 px affiche Nomenclature. L'inspecteur devient une feuille, comme la fiche d'un terme.

3a · Renommages, filtrés par l'arbre

Tokens · Renommages
  1. La barre du haut porte le nom UCM Token Architect.
  2. Le bouton Configuration de Nomenclature rejoint la barre du haut. La Configuration vaut pour tout le plugin.
  3. Les onglets de l'explorateur disparaissent. La table montre toujours les variables.
  4. La barre latérale reprend Nomenclature sans changement. L'en-tête de Nomenclature disparaît.
  5. Un quatrième onglet, Structure, rejoint Renommages, Questions et Règles.
  6. Une collection choisie dans l'arbre filtre la liste. Un bandeau le dit et rend la liste entière.
  7. Le pied ne dit plus « Lecture seule ».

3b · Questions et Règles

Tokens · Questions
  1. L'onglet Questions ne change pas.
Tokens · Règles
  1. L'onglet Règles ne change pas.
  2. Un clic sur un terme ouvre sa fiche et marque ses variables dans la table.

3c · Structure

Tokens · Structure
  1. L'onglet reprend les diagnostics de l'explorateur et les règles du profil UCM.
  2. Les constats se rangent par sujet : chaînes, modes, valeurs, couches, portées.
  3. Chaque constat garde la forme d'une carte de Nomenclature.
  4. Seules les portées se corrigent ici. Leur carte a une case.
  5. Les autres constats renvoient à la fiche de la variable.
  6. Appliquer range la correction dans l'Historique.

3d · La fiche d'une variable

Tokens · Fiche d'une variable
  1. Un clic sur un nom de la table ouvre la fiche. Elle glisse sur la barre latérale.
  2. La fiche reprend la feuille d'un terme de Nomenclature.
  3. Le titre colore les groupes en orchidée et la variable en olive.
  4. La chaîne de chaque mode reprend l'inspecteur de l'explorateur.
  5. « Comparer avec » remplace l'onglet Comparer.
  6. « Utilisée par » remplace l'onglet Dépendants.
  7. La croix rend Nomenclature, sur l'onglet qui était ouvert.

3e · Une bibliothèque lue depuis le fichier des composants

Tokens · Bibliothèque
  1. Le fichier des composants n'a pas de variable locale. Le mode Tokens montre la bibliothèque de tokens.
  2. Les noms s'affichent tout de suite.
  3. Les valeurs d'un groupe se chargent à son ouverture.
  4. Nomenclature montre ses règles. Les renommages se font dans le fichier des tokens.

4 · Mode Composant

La fenêtre passe à 900 × 760. La vue Composant garde 400 px à gauche. La barre latérale de 500 px montre l'analyse. Le composant d'exemple est Alert, sélectionné sur son variant info · standard.

4a · Constats

Composant · Constats
  1. La matrice des variants rejoint la vue Composant, sous l'en-tête.
  2. Chaque case compte les constats de son variant. Sa couleur suit le constat le plus grave.
  3. Une case en pointillés signale une combinaison absente.
  4. Un clic sur une case lit ce variant à gauche.
  5. Le résumé donne le composant, l'heure de l'analyse et le compte par gravité.
  6. Actualiser relance l'analyse. Elle ne se relance jamais seule.
  7. Les onglets suivent l'ordre du travail : constater, corriger, trancher.
  8. Les constats se rangent par sujet, comme les intertitres de Renommages.
  9. Chaque constat dit ce qui ne va pas, puis où.
  10. La dernière ligne dit comment il se règle : correction prête, question, ou geste dans Figma.

4b · Un constat ouvert

Composant · Constat ouvert
  1. Le constat ouvert donne les faits lus : calque, champ, variable liée, variable attendue.
  2. « Sélectionner dans Figma » sélectionne le calque et le montre à l'écran.
  3. Le survol entoure le calque dans l'aperçu, comme aujourd'hui.
  4. « Ignorer » range le choix dans le fichier. Toute l'équipe le voit.
  5. Un constat ignoré passe en bas de la liste, grisé, avec « Ne plus ignorer ».

4c · Corrections

Composant · Corrections
  1. L'onglet reprend Renommages : cartes cochées, colonnes Aujourd'hui et Après, pied Appliquer.
  2. Une carte groupe les liaisons d'une même cause.
  3. Seule change la partie du nom qui change.
  4. Chaque ligne nomme son calque et son variant.
  5. La propagation demande d'abord le variant de référence. Aucun n'est choisi d'avance.
  6. Une correction n'apparaît ici que si elle est exacte. Le reste va dans Questions.

4d · Après Appliquer

Composant · Après Appliquer
  1. La ligne verte reprend celle de Renommages.
  2. Elle dit que Ctrl+Z défait le lot.
  3. Le bandeau dit que l'analyse est périmée. Les constats restent lisibles jusqu'à Actualiser.

4e · Questions

Composant · Questions
  1. Les cartes reprennent celles de Questions dans Nomenclature.
  2. Aucune réponse n'est mise en avant. Chaque candidat a son bouton.
  3. Renommer une valeur de variante prévient que le code devra suivre.
  4. La seconde réponse prépare une règle pour Nomenclature, dans le fichier des tokens.

4f · Contraste et accessibilité

Composant · Contraste
  1. Chaque mesure montre la paire, le rapport et le seuil.
  2. Elle nomme la marque et le thème mesurés.
  3. Un fond en dégradé dit que la mesure n'a pas pu se faire.
  4. La taille de cible compare la zone cliquable à 24 px.
  5. Une ligne rappelle que la mesure porte sur le dessin Figma.

4g · Règles d'usage

Composant · Règles d'usage
  1. Un composant sans règles reçoit un bouton « Générer les règles ».
  2. La génération pose l'instance de règles à côté du composant, comme l'exporteur aujourd'hui.
  3. Une propriété sans règle reste un constat. Le designer l'ajoute dans Figma.

5 · Génération des tokens

Le parcours de l'aperçu de génération, en quatre écrans. Il passe du fichier des composants au fichier des tokens, puis revient.

5a · Composant : préparer
  1. « Préparer les tokens » part d'un constat d'oubli, ou du menu du résumé.
  2. La feuille pose les questions. Aucune réponse n'est cochée.
  3. Les cibles s'affichent au fur et à mesure des réponses.
  4. Préparer reste inactif tant qu'une question reste.
  5. « Copier le plan en texte » sert à l'envoyer à un autre designer.
5b · Composant : plan prêt
  1. Le bandeau dit où continuer.
  2. Il dit que le plan reste sur ce poste.
5c · Tokens : créer
  1. Le plan attend en tête de la barre latérale.
  2. La feuille montre les variables à créer et leur cible.
  3. Les variables qui existent déjà restent telles quelles.
  4. Créer range la création dans l'Historique.
5d · Composant : lier
  1. Après la publication de la bibliothèque, Corrections propose les liaisons.
  2. Les liaisons viennent du plan. Elles sont exactes.
  3. Une variable pas encore publiée laisse sa ligne en attente.

6 · Configuration

Une seule Configuration pour le plugin. Elle s'ouvre en page entière depuis la barre du haut, comme dans Nomenclature.

Configuration · Réglages
  1. Les sections de Nomenclature ne changent pas.
  2. « Bibliothèque de tokens » dit laquelle le mode Composant lit, et pourquoi.
  3. « Accessibilité » choisit le niveau de contraste, AA ou AAA.
Configuration · Historique
  1. L'Historique garde la dernière écriture de chaque sorte sur les variables.
  2. Renommage, création de variables, portées : chacun a son bouton Annuler.
  3. Les corrections d'un composant se défont par Ctrl+Z. Elles n'entrent pas ici.

Fichier hors UCM
  1. Une analyse partielle ou arrêtée ne dit jamais « aucun constat ».
  2. Une erreur du moteur s'affiche avec le texte de l'exporteur.
  3. Hors UCM, la navigation reste entière. Le bouton ouvre la Configuration sur la déclaration.

8 · Styles communs

Les éléments partagés par les deux modes. Les pastilles orchidée et olive viennent de Nomenclature et désignent un groupe ou une variable partout dans le plugin.
