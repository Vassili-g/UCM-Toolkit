Historique de la Configuration

La Configuration d'UCM Nomenclature prend deux onglets, sur le modèle de Palettes. Le premier garde les réglages actuels. Le second, « Historique », permet de revenir à l'état d'avant le dernier renommage. Les cadres sont les écrans réels de la galerie sombre, modifiés avec les classes du plugin. Les repères roses montrent ce qui change.

Ce que le plugin garde déjà

Avant d'écrire un nom, « Appliquer » range un journal dans le fichier. Ce journal garde l'ancien et le nouveau nom de chaque objet renommé. Un import de règles garde de même chaque règle qu'il remplace.

La Configuration actuelle s'en sert pour ses deux boutons « Annuler ». Elle ne montre pas les noms concernés. Le designer découvre après coup les noms qui n'ont pas pu revenir.

L'Historique affiche ce journal. Il n'ajoute aucun stockage.

Configuration actuelle, après un renommage et un import

2 · Proposé : deux onglets

Onglet Réglages
  1. Les onglets et la phrase en dessous reprennent la Configuration de Palettes.
  2. Les sections « Collections analysées » et « Règles de ce fichier » ne changent pas.
  3. « Dernier renommage » et « Dernier import » passent dans l'Historique.
Onglet Historique
  1. La date donne le jour en plus de l'heure. Le journal reste dans le fichier d'un jour à l'autre.
  2. Une phrase rappelle que seul le dernier renommage est gardé.
  3. Le diff reprend la carte dépliée de l'onglet Renommages, sans les cases.
  4. Les noms actuels sont à gauche et les anciens noms à droite.
  5. Le rouge barré marque ce qui disparaît. Le vert marque ce qui revient.
  6. Chaque collection a sa carte. Seule la première est ouverte.
  7. Chaque bouton nomme ce qu'il annule.
  8. Le diff de l'import affiche les règles avec les jetons gris de l'onglet Règles.
  9. La ligne grise sur Figma dépend de la question Q2.

3 · Les cas de l'Historique

3a · Des noms ne reviendront pas
  1. Le plugin annonce avant le clic les noms qui ne reviendront pas.
  2. Un nom changé dans Figma depuis le renommage reste gris.
  3. Une collection décochée indique comment rétablir ses noms.
  4. Le bouton reste actif. Les autres noms reviennent normalement.
3b · Confirmation
  1. La fenêtre de confirmation actuelle ne change pas.
3c · Après l'annulation
  1. La ligne verte reprend celle de l'onglet Renommages.
  2. Il n'y a pas de bouton « Refaire ». L'onglet Renommages propose de nouveau les mêmes noms.
  3. L'import reste annulable à part.
3d · Rien à annuler
  1. L'onglet reste visible. Le designer sait dès le début qu'un retour en arrière existe.

4 · Dans l'onglet Renommages, juste après « Appliquer »

La ligne verte indique l'Historique
  1. « Annuler » reste dans la ligne verte.
  2. Une ligne de plus indique où retrouver les anciens noms plus tard.

5 · Variante écartée : plusieurs renommages

Plusieurs renommages · non retenue
  1. Les annulations devraient se faire du plus récent au plus ancien.
  2. Les anciens renommages serviraient seulement à lire.
  3. Le fichier grossirait à chaque renommage.
  4. La demande porte sur le dernier renommage.

7 · Ce que l'implémentation demande

  • Le bilan transmet les lignes du journal avec leur sort.
  • Le sort se calcule avec la règle de l'annulation.
  • Le bilan transmet aussi les règles d'avant et d'après l'import.
  • La Configuration se divise en deux onglets du socle.
  • Le format du journal ne change pas.
